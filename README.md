# 先进通用履带底盘工程

AGTC（Advanced General-purpose Tracked Chassis）面向户外应用，围绕履带底盘开展感知、定位、行驶与云台联合规划及电控研发。
算法、硬件和机械资料集中在本仓库维护，模块入口如下。
具体设计与操作要求以各模块文档为准。
电力板卡每板只维护《设计需求.md》和《设计细节.md》两份现行设计文档，统一入口见[电力工程](电力/README.md)；原理图、BOM及机器证据作为附件引用。

## 整车设计目标与验收顺序

首个整车里程碑是在受控平地和约定限速内，从静止完成上电、自主到点、低速停稳及异常停驱。用户确认整车含载荷总重 30 kg、平地最高速度 15 km/h、最大爬坡坡度 60%（高差与水平距离之比，约 31°）。首版还需验证受控下坡，先由现有硬件反算坡度、速度与持续时间的组合。平地拒充制动、最大爬坡和受控下坡分别校核。电力按 0–60 °C 环境校核，保留双电机同时各 1.8 kW 输入峰值能力、16 A 整包净充电上限和独立稳压模块。电制动是整车的制动路径。比较模型按制动电阻热容量无限处理，实体选型须核额定功率、散热和脉冲能力。双机同时峰值须覆盖从静止到 15 km/h 的启动过程，实际加速时长按牵引和供电验证确定。首版平地制动按 15 km/h、自制动请求至停稳 3 m 验证，优先闭合电池和超容同时拒充。爬坡速度及持续时间、下坡与驻坡要求另核。 [机械参数基线](机械/参数基线.json) · [电力基本设计](电力/基本设计.md)

供电、运动许可和吸能状态按整车合同统一复核。各负责人用同一张表交付首版样车的原理和实测证据。 [整车供电和运动许可合同](电力/基本设计.md#整车供电和运动许可合同待各负责人联合复核) · [首版样车联合验收表](电力/基本设计.md#首版样车联合验收表)

自主运行集成端负责把策略动作映射为左右履带速度，并在发送前执行该工况批准的速度和加减速边界。FOC 负责本地驱动许可、命令过期和硬件保护。上层失去必需观测、任一侧反馈失效或策略输出非有限值时，停止发送非零运动指令。板端分别验收上层发零和通信中断时的退出路径，记录触发时刻、最后非零指令、两侧实际退出和车体停稳。故障恢复后，重新取得双侧有效状态和驱动许可才可接受新会话的运动指令。 [自主运行回放要求](算法/仿真训练环境/README.md) · [板端交接](固件/README.md)

### 分工与交接

- **整车协调**负责从设计到样车的任务分派、依赖排序、交付跟进和跨模块验收。协调方明确工况边界、接口和放行条件，各子项目负责人维护具体设计与验证证据。
- **电力**由各板现有对话负责。BMS 牵头预充和合闸，稳压牵头拒充制动和中央吸能，FOC 负责两侧驱动退出、本地过压和回生接口，水泵负责其负载、使能时序和停机边界。
- **通信、感知与定位**分别维护本模块的参数和接口，交付时间戳、坐标、单位及有效性约定，并提供联调所需样例。传感器安装位姿由人类机械负责人确认。
- **神经网络研究**负责模型与策略设计，交付检查点、观测与动作契约及评估证据。**自主运行集成与离线回放**负责仿真环境、集成评估和板端回放交接。
- **人类负责人**负责机械设计、PCB 设计、制造、装配、固件实施和实物测试。子项目先交付对应的接口、设计资料和测试条件，由整车协调跟进交接。各阶段负责人按供电和运动安全、仿真闭环、板端回放、受控实车的顺序交付放行证据。

接口由输出方维护，接收方按样例或试验确认。沿用现有对话与验证入口。单板确需拆分时，按采购、原理验证和图面等独立工作分派低额度子智能体，由板卡负责人统一写入及验收。共用器件由项目器件库统一维护。

## 获取工程

安装 Git 和 Git LFS，并确认具有仓库访问权限。Windows 克隆需启用长路径并初始化第三方 submodule：

```powershell
git lfs install
git -c core.longpaths=true clone --config core.longpaths=true --recurse-submodules https://github.com/w3743/AGTC.git
cd AGTC
git lfs pull
```

CAD、模型等大型二进制由 Git LFS 管理；第三方源码通过 submodule 固定版本。克隆后按各模块说明准备运行环境。
