# MP2643 替换影响清单（只读库存）

日期：2026-10-12。此清单只盘点现有源和更新脚本，不修改原理图、BOM 或连接源，也未运行测试。

## 现态

`README.md` 已禁止 MA5421-ALD，并将 LTC3300/MA5421 原生工程、BOM 和连接标为替换前快照；主动均衡暂停布局与采购。当前源中仍有 2 颗 LTC3300-1、9 只 MA5421-ALD，未发现 MP2643 位号或新均衡页组。MP2643 只在[候选采购核对](国产均衡候选采购.md)中作为比较方案：9S 相邻级需要 8 颗；该记录不是批准 BOM 或原理图。

## 更新脚本行为与风险

- `同步构建输入.py` 的器件模板只覆盖已编码的电阻、电容、WDT_SUP、少数特例和服务端口；遇到未配置的新 MP2643/电感等位号会在 `template()` 抛出 `ValueError`。新器件需要先补齐源记录、封装/符号映射和明确的 pageGroup/坐标，不能只把 MP2643 加进 AFE JSON。
- `原生更新.py` 以 `sys.argv[2:]` 为目标 pageGroup（不传则遍历页面映射）。每组先 `openDocument(PAGE_ID)`，再读取当前页器件、规划新器件并校验 pin map；之后删除该页全部 netport 和 wire（第 49–84 行），只按该组 `entries` 重建 pin stub/port（第 86–106 行）。
- 因而它会覆盖“所选页”的全部导线/端口，不是按改动位号局部重连。若有未列入 entries 的现存连接或页面器件，连接会丢；entries 未列出的旧器件也不会自动删除（除两个脚本硬编码位号），会留下断连旧器件。执行中途失败没有回滚，保存只在末尾发生。
- `openDocument` 后调用的 `getAll()` 没传页面 ID，代码意图是当前文档/页作用域；本清单没有做新一轮官方 API 页面级实测，不能把页面隔离当作本轮验收证据。

## 最安全的原位替换准备

1. 先冻结新架构的完整 9S 接法和 8 个相邻级的逐级引脚/网络/控制默认态；明确旧 LTC 支持电路、9 路磁件/MOS/采样/RC、NET/PORT 中哪些保留、删除或重命名。更新逻辑源、BOM、连接表、构建清单、器件映射及页面映射，保持来源一致。
2. 暂不直接用现有 `原生更新.py` 做 subset 替换。先改为**显式的目标页白名单 + 完整目标页清单 + obsolete refs 删除清单**，并在创建/引脚校验通过后才删除旧器件；只允许目标 page ID 上的修改。若无法保证完整页清单，则应改成按目标器件及其关联 wire/port 精确更新，保留其它对象。
3. 对目标页逐页施工，并为原生工程留可恢复副本。每页更新后用官方 API 读回目标页的位号、引脚网络和 netport/wire；再读取所有非目标页，比对更新前后 pin→net，确保其连接未变。最后重新导出官方网表，对新源/BOM/连接表做一致性对照。

现有全页回读与官方网表证据在 README 中明确属于 LTC/MA5421 替换前快照；不能作为 MP2643 设计或页面保全验收。
