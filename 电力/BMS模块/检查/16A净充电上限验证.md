# 9S4P 电池净充电 16 A 上限模型验证

## 当前结论（2026-10-15）

**参考 CCL 算法及参数模型 PASS；固件、硬件、台架与整车发布 BLOCKED。** 16 A 是用户设定的净充电上限，不是要求各温度必须交付的最低电流。BQ76952 OCC code 3 保护候选保持不变，正常充电由本地 CCL 按最坏测量误差、支路分配、温度资格和源端动态余量限幅。

当前参考算法已在 [BMS充电CCL算法修复与复查报告](未通过项修复/BMS充电CCL算法修复与复查.md) 中记录。代码为 `仿真/源码/verify_charge_limit_16a.py`，参数为 `仿真/输入/16A净充电上限验证_input.json`，最新模型和自动检查分别为 `仿真/结果/16A净充电上限验证_result.json` 与本目录 `16A净充电上限验证.json`。

主要条件模型结果：

- OCC code 3 的温度补偿早动作角约 **7.901 A**，规划峰值线为 **7.401 A**（另留 0.5 A 工程规划余量；不是器件保证）。
- 假设 alpha≤1/3 已验证、分流器上界 75°C、路径欠读≤20 µΩ、源端动态超调≤1 A时，16 A请求被限到 **5.5 A**，预测峰值 **7.328 A**、最大支路 **2.443 A**。
- alpha 未验证时回退 alpha=1.0，只有“各并联支路充电方向同向、无反向支路/循环电流”已资格时，16 A 请求才限到 **2.3 A**，模型预测单支路峰值 **3.893 A**；该额外资格当前未通过，缺失时算法返回 **CCL=0**。若使用经验证 alpha，其证明须覆盖最坏支路电流及循环电流影响。
- 温度资格要求对**全部36颗电芯**提供保守温度下界与上界，保证每颗区间都在23–27°C；仅有上界、代表性NTC或上/下界反向都不足。缺失、非数/NaN、过期、下界<23°C或上界>27°C时按 **CCL=0**；其它传感器、校准/寄存器读回、源端动态边界或采样路径条件缺失/超限也 fail-closed 为零。

以上为可复算的条件模型，不是已部署固件、实测电流、保护协调或电池包额定值。36颗电芯温度上下界覆盖、无支路反向/循环电流资格或纳入循环电流的alpha边界、BQ电流校准/OCC读回、实际Kelvin路径、源端本地响应/超调、75°C分流器热界限及超容吸收仍待实物资格；release gates 目前保持未通过。TI BQ76952 数据表/技术参考手册及 EVE 原厂电芯资料见修复报告。

总线能量参数屏查仍为 756 组；60 mF、37.8 V至45 V 的电容能量余量 17.8848 J。该结果不证明任何电源停机时延或超容硬件能力。
