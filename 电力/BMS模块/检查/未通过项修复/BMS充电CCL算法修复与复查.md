# BMS 充电 CCL 算法修复与复查（2026-10-15）

## 判定

**条件模型 PASS；固件、硬件和整车发布 BLOCKED。** 16 A 是用户净充电上限，不是交付下限。保留 BQ76952 OCC code 3 候选，不提高门限、不删除保护。Python 参考算法按单体温度、支路电流、OCC 早动作角、测量误差、路径误差和源端动态预算限幅；模型尚未部署到固件或充电源。

## 本轮修复与设计边界

- **16 A 与 OCC 冲突已按安全上限处理。** RSHUNT 0.5 mΩ ±1%、±50 ppm/°C、OCC阈值小设定误差和75°C候选角得到 code 3 早动作 **7.901 A**、晚动作 **17.519 A**。正常峰值模型线为早动作角减0.5 A工程余量，即 **7.401 A**；此余量不是芯片保证。保留 code 3，不把 OCC 当恒流调节器。
- **CCL 算法执行动态/测量限幅。** BQ 单边测量欠读预算 **0.3957 A**；采样路径误差接受上界 **20 µΩ**；源端总正向超调接受上界 **1.0 A**，条件为 `max(0,dI/dt) × 本地响应时间 + 额外峰值超调 ≤ 1.0 A`。后两项均为设计验收界限，尚非板上实测/当前硬件保证。任一边界未资格或越限时算法置零。
- **温度资格现在检查全部36颗电芯的保守区间。** 输入必须能证明每颗电芯真实温度被覆盖，算法使用全包最冷下界与最暖上界，要求下界 `≥23°C`、上界 `≤27°C` 且下界不大于上界。缺失、陈旧、非数/NaN、上下界反向或超出窗口均返回 CCL=0。当前三个代表区NTC没有证明覆盖全部电芯，实际门禁仍为 false；无 EVE 电流-温度曲线，不外推窗口外的4 A/cell测试值。
- **未验证均流时的 alpha=1 回退增加了反向支路门禁。** 对16 A请求，在 alpha=1/3 的假设已验证、温度区间合格、75°C分流器角、20 µΩ路径误差及1 A动态预算均成立的假设案例中，命令 **5.5 A**，模型峰值 **7.328 A**、最大支路 **2.443 A**。这些前提未实物资格。未验证 alpha 时只有确认4条并联支路充电电流同向、无支路反向/循环电流，才可用 alpha=1.0 作为最大支路份额：该条件案例把16 A请求限为 **2.3 A**、模型单支路峰值 **3.893 A**。新增 `no_counterflow_current_qualified` 门禁；资格缺失时实测设计状态应输出 CCL=0。若未来以实测 alpha 代替回退，alpha 必须覆盖最坏支路充电电流及循环电流影响。
- **新增故障注入。** 覆盖任一单体低温（下界5°C）、上下界反向、NaN温度界、缺少全36颗资格、alpha回退但无无反向支路资格，以及既有过温/陈旧传感器/源超调/路径误差/单体余量/alpha无效等用例。

## 待追加至共享项目要求的句子

按主代理协调，本报告临时记录建议，**没有直接写入共享 `BMS模块/项目要求.md`**：

> 充电 CCL 将16 A作为净充电上限而非交付下限，保留OCC code 3保护；正常CCL须以覆盖全部36颗电芯的保守温度上下界、并联支路最大充电电流份额、最坏电流测量与采样路径误差及已资格的本地源端动态上界计算。温度上下界必须保证全部电芯处于已证明的最大充电电流温区；有效alpha不得低于1/4的四支路同向数学下界；未验证alpha时，仅在无支路反向/循环电流已资格时按alpha=1.0回退，否则CCL=0；以验证alpha替代时须覆盖最坏支路电流及循环电流影响。不得为提高正常充电电流放宽保护；模型结果不得标成固件、实物或整车验收。
