# DRC 供应商编号与采购身份核查

日期：2026-10-16。范围为只读核对 DRC 导出、官方 EasyEDA 库查询结果、保存的工程快照和共用库原生片段；本记录未修改 CAD。

## 查询结果

对 188 个 DRC 涉及 Ref 汇总出 41 个唯一供应商 C 号，使用官方 API `LIB_Device.getByLcscIds` 分批查询；41 个 C 号均返回一条目录记录。查询原始结果见[批量库查询证据](./supplier-id-library-query.json)，Ref 与采购 MPN 对照见[采购身份核验数据](./值建议与采购身份核验.json)。

按实例 MPN 与目录 `Manufacturer Part` 原文比较：

| 分类 | 数量 | 处理 |
| --- | ---: | --- |
| 原文完全一致 | 178 | 保留实际采购 MPN 和 C 号；不因告警批量改写。 |
| MPN 仅多厂家前缀 | 7 | 保留采购 MPN；厂家前缀与料号主体分别记录，不自动删前缀。 |
| 仅空格格式差异 | 2 | 保留采购 MPN；属于格式差异，不替换采购身份。 |
| 器件等级不一致 | 1 | `U_LOAD_POWER_VALID` 的实际/BOM MPN 是 `VO617A-2X007T`，C 号 `C17528767` 查询到的目录器件是 `VO617A-4X007T`。这是唯一核实到的不同采购型号。保留 2X 的 MPN；不得改成 4X。此 C 号不能再作为 2X 的供应商身份，若后续修改工程，只应移除该错误映射并把 2X 的准确 C 号标为待核实。两档 CTR 不同，见[Vishay 官方数据手册](https://www.vishay.com/docs/83430/vo617a.pdf)。 |

7 个厂家前缀差异为：`C_CP1`（Murata）、`D_TVS`（Littelfuse）、`DZ_QPRE`（onsemi）、`U_GATE1`、`U_POR`、`U_SEQ`、`U_TIMER`（TI）。两条空格差异是 `NTC_BOARD`、`NTC_MOS`：实例为 `MF52A103F3950(A1)`，目录为 `MF52A103F3950 (A1)`。

保存的 API 快照中，188/188 个实例的供应商名、C 号和封装名称均与该 C 号查询结果一致。另有 9 个 `C9900019564` 实例的工程厂家是 Murata，而对应目录记录的 `Manufacturer` 为空；其余实例的厂家字段与目录相符。这是独立的目录属性缺项，不足以证明采购 C 号虚假。

## C9900019564（含 C_SRP）

查询记录返回 `Manufacturer Part = GRM188R72A104KA35J`、`Supplier Part = C9900019564`、封装 `C0603`、供应商 `LCSC`，但厂家和 Datasheet 为空，目录名称也只有 MPN。`C_SRP` 的[DEVICE 原生片段](../../../元件封装库/原生片段/DEVICE/6cb3948a430ec097f311a203746e8bf22bc14f07758ad03ffcf555baaac035e8.jsonl)记录的 source 指向同一个目录设备 UUID 和库 UUID；因此这是从该目录条目克隆出的载体，并非工程内手造载体。该证据只能证明本地载体与目录记录的来源，不能证明这个 C 号目前有效或由 LCSC 分配给该 MPN。

LCSC 公开站内精确检索没有找到该 C 号的商品页；未检出不等于证明该号不存在。Murata 官网确认 `GRM188R72A104KA35J` 是真实的 0.1 µF、100 V、X7R、0603 器件，但不确认 `C9900019564` 的分配关系（[Murata 官方产品页](https://www.murata.com/products/productdetail?partno=GRM188R72A104KA35%23)）。结论标记为“供应商编号映射待核实”：保留采购 MPN，不将 C 号判为伪号，也不清空该组 C 号以压告警；采购前应以 LCSC 可核验商品记录或采购凭证确认。

## 属性恢复与剩余告警

187 个可匹配载体恢复了三个公共目录属性：`LCSC Part Name`、`Supplier Footprint`、`JLCPCB Part Class`。原日志有 7 组“属性与供应商编号不匹配”告警；保存的[官方 API 快照](./post-api-snapshot.json)只记录 `warn count = 8`，没有剩余告警的 Ref 或逐项比较字段，因此本记录不把八条告警归到上述八个身份差异，也不据此推断其实际身份。早先导出按规则文本分组列出了 188 个 Ref；分组文本本身没有指出触发的具体字段。

## 标准化接口核对

本机 `.agents/skills/easyeda-api-skill` 的 API 文档中未找到可执行“器件标准化”或替换现有原理图器件库绑定的 API/CLI。文档只列出 `SYS_PanelControl.openLeftPanel(DEVICE_STANDARDIZATION)` 用于打开标准化面板；`LIB_Device.get/getByLcscIds/search/modify` 是库器件查询或库记录操作，`SCH_PrimitiveComponent.modify` 没有替换器件库绑定的参数。故不能把属性修改 API 当作器件标准化 API，也没有用库字段改写采购身份。

接口依据：[LIB_Device](../../../.agents/skills/easyeda-api-skill/references/classes/LIB_Device.md)、[SCH_PrimitiveComponent](../../../.agents/skills/easyeda-api-skill/references/classes/SCH_PrimitiveComponent.md)、[SYS_PanelControl](../../../.agents/skills/easyeda-api-skill/references/classes/SYS_PanelControl.md)、[左侧面板标签枚举](../../../.agents/skills/easyeda-api-skill/references/enums/ESYS_LeftPanelTab.md)。

## 本轮最终处置（当前工程）

实际采购 MPN `VO617A-2X007T` 保留；其错误的 4X 目录映射现已改为 `supplier=UNVERIFIED`、`supplierId=UNVERIFIED_2X`。这是明确禁止下单的待核实占位，不是有效采购编号。其余可匹配载体的恢复未替换实际采购 MPN。板外 `R_PRE` 已恢复为 `CJP300J8R2J`、8.2Ω、±5%、300W，其两针已在官方重开快照和逐针几何核对中连接至 QPRE_SW/PACK+；板外件不重复进入板内 BOM 或 PCB。

当前 P1 SHA256 为 `7338c38954e8d456c87ed69aad2c4ac23593f4b53c54dee3c6d6a64c38cad88a`。官方重开为 208 个器件、700 个引脚、7 条警告，逐条警告文本尚不可由 API 获取。不能把此汇总等同于原日志 7 组的逐项复核；剩余规则、Ref 和属性差异须以用户新导出明细确认。额外恢复 1127 项目录电气属性的试验未减少告警，现已回退至上述 SHA，未采用该试验。
