# 9S BMS 项目要求

更新日期：2026-10-22。适用范围：本电力项目的 BMS 模块，以及它与太阳能充电、驱动回馈、超容双向 DC/DC 的接口。

本文件保存用户要求及其来源，作为后续接力的必读入口。它不是电气验收报告。设计实现和验证证据分别保存在原理图准备、原生工程、检查和仿真目录。

## 1. 使用与更新规则

1. 开始或接力 BMS 工作时，先读本文件、模块 README 和当前设计状态，再核对本轮源文件。数量、价格和历史 PASS 不直接沿用。
2. 用户新要求立即更新本文件；同一事项以用户较新的明确指示为准。已经授权的可回退工作直接推进。
3. 区分“用户明确要求”“既有工程输入”“代理提出的候选”。不得把候选电路、某个保护器件或历史实现永久固化为用户要求。
4. 需求冲突或缺失参数确实影响结论时，说明影响并提问；可独立完成的查找、计算和验证继续推进。
5. 本文件原位维护，只保留一份当前要求。详细计算和过程记录不堆入本文件。

## 4. 设计取舍与验证要求

### 4.1 器件与保护精简

- 优先删除整块重复功能和专属外围，再归并同功能精确型号。少增件即可减少独有料号时优先考虑；为省一两种料号大幅增件的方案重新评估；并将系统能耗、热损和静态功耗与芯片及高价值器件、总件数、焊点和复杂度共同纳入优化。
- 当前重点是整颗保护/控制芯片、光耦、隔离收发器、功率MOS、电源模块和均衡电感等高价值器件。按可删除功能块、成本、独有MPN收益及验证代价排序；不再以电阻串并联凑值作为本轮精简方向。
- 每项保护写清：防什么具体故障、现有芯片是否已覆盖、能否合并、删掉后由谁接替，以及失电/复位/通信丢失时的实际动作。
- 保护、调节、浪涌钳位、故障锁存与隔离分开判断；名称相近不表示功能重复。保护动作阈值与正常控制能力也不能混为一谈。
- 替换核对阻容误差、温漂、有效电容量、耐压、功耗、驱动和时序、默认态、引脚、封装及精确采购型号。计算结果必须绑定所用输入与适用工况。

### 4.2 独立冷却板接口

- BMS保留温度采集，通过现有CAN上传温度；独立冷却板自行决定风扇转速。BMS不设计风扇电源、PWM驱动、测速或专用风扇连接器。
- 温度报文应区分有效、无效及过期数据，具体信号定义、周期与接收方策略由后续接口和固件落实；当前硬件交付不等于CAN通信已运行验证。
- BMS本地过温、低温禁充及必要保护继续独立成立，不能依赖冷却板或CAN可用。

### 4.3 行进充电与动能回收

- 以电池端净电流统一核算太阳能、驱动回馈、超容 DC/DC 与负载叠加，避免多个源各自使用整份充电余量。
- 分清 BMS 允许充电能力、充电器/MPPT 的恒流恒压调节、FOC 回馈调节及超容吸收的职责。太阳能板不能直接接电池或母线冒充受控充电器。
- 核对满电、低温禁充、过温、能力过期/通信失联、充电 MOS 打开，以及太阳能和回馈同时出现时的处置。
- 电池净充电允许上界16A，正常控制设置须扣除误差和动态余量；OCC只作过流切断，不作为16A恒流器。超额回收优先分配给超容，按其有效可吸收功率及剩余能量约束，能力不足须源端减功率。
- 电池不能吸能时，先明确能源源头减功率及母线剩余能量去向；TVS 不计作持续制动负载。隔着 DC/DC 的超容不计为母线瞬时直连电容。
- DRIVE/CHARGE 协议的互斥限制须与边走边充、回馈目标核对；不能只更新描述而保留冲突字段规则。

### 4.4 证据与交付

- 区分候选、计算通过、模型验证、官方 CAD 保存重开核对、ERC/DRC 和实物验收。未完成的项目明确记录，不沿用历史 PASS。
- 无样板阶段完成能够完成的计算与仿真，列出模型假设及首板需确认的剩余项目。
- 原生工程优先通过官方API读取、修改和保存；API无法持久化的TEXT清理由官方工程格式工作流与官方文件API完成，逐条白名单及非TEXT字节比对后重开验证；正式修改后核对源清单、逐针网络、MPN 和计数，并运行共用库同步与只读检查。
- 一份当前原生工程、一套当前交付，原位更新；备份和过程材料按项目归档规则保存。不得以修改文件名/显示属性代替真实器件库绑定。
