# 官方 sle_measure_dis 基线实测（2026-10-25）

> 目的：在**纯官方固件**（`Artifacts/server`、`Artifacts/client`）上采集未做任何应用层校准的原始距离，
> 用于判断「其它距离点误差大」是算法固有还是我们改动引入。环境：桌面、两板天线平行、无遮挡、静置。

## 测试条件

- 固件：`Artifacts\server\bs21e_all.fwpkg` → A 板 COM22；`Artifacts\client\bs21e_all.fwpkg` → B 板 COM23
  （官方 `application/samples/products/sle_measure_dis`，未改任何代码）
- 串口 115200 8N1；server 端打印 `SLEM get distance done. distance:X.XXX, time = N ms.`
- 每次静置后连续采集 15~20 秒，取有效行（剔除 `distance:-1.000` 错误帧）

## 实测结果

| 实际距离 | 官方原始输出（dist_first，未校准） | 样本 | σ |
|---|---|---|---|
| 0.50 m | 1.553 / 1.554 / 1.557 / 1.559 / 1.568 / 1.570 → **均值 1.560 m** | 6 | ≈0.006 m |
| 1.00 m | 2.145 / 2.150 / 2.162 / 2.167 / 2.168 / 2.171 → **均值 2.161 m** | 6 | ≈0.010 m |

> 另有零星 `distance:-1.000` 帧（算法返回错误码时输出模板值，见 `Docs/range_link/README.md`「算法」小节）。

## 结论（算术推导，非猜测）

1. 官方原始距离 ≈ **1.2006 × 真值 + 0.9599 m**（两点线性拟合，单位米，`R²=1`）。
   即：**大常偏置（约 +1m）+ 1.2 倍刻度**，而**不是**噪声问题（σ 仅 1cm 量级）。
2. 若按官方文档「1m 处均值 − 1 = 校准值」只做偏移校准（calib=1.161 m）：
   - 1.0m → 2.161−1.161 = **1.000 m**（准确）
   - 0.5m → 1.560−1.161 = **0.399 m**（误差 −10.1 cm）
   - 2.0m（按线性模型外推）→ 3.361−1.161 = **2.200 m**（误差 +20 cm）
   → 说明官方「单点偏移校准」只在 1m 附近准，**其它点误差随距离线性增大**，这正是用户反馈的现象。
3. 若做两点线性校准（用 0.5m 与 1.0m 两点）：
   `d_cal = (raw − 0.9599) / 1.2006 = raw × 0.8329 − 0.7995`
   - 0.5m → **0.500 m**，1.0m → **1.000 m**（两点精确）
   - 对外推 2m 的预测：raw≈3.361 → 2.000 m（前提：线性模型在 2m 仍成立，需实测确认）
4. 因此修正方向：**用两/多点线性校准替代单点偏移与错误的 0.454 比例**；公式与参数见
   `SDK\bearpi-pico_h2821e\application\samples\products\sle_range_link\Kconfig`
   （`RANGE_LINK_CALIB_SCALE_PM` / `RANGE_LINK_CALIB_MM`）。
