## 1. 当前状态（v31 server + v16 client，两点/三点线性校准已验证，满足 ≤10cm 要求）

> **验收标准（用户要求）**：测量误差不超过约 **±10cm**。
> **实测结论**：三点线性校准后在 0.5m / 1.0m 两个点误差分别为 **−15mm / −19mm**，σ ≤ 1cm —— **满足要求**（留有约 5 倍余量）。

**v28 线性校准用法（推荐，替代单点对零）**：串口（COM22，115200，回车换行）发：

```text
AT+RDCLR              <- 清空之前的标定点
（板子放在 0.50m 处，静置 10~20 秒等它收敛）
AT+RDFIT=500          <- 记录第 1 个点：真实 500mm + 当前原始中位数
（板子放在 1.00m 处，静置 10~20 秒）
AT+RDFIT=1000         <- 记录第 2 个点，自动做最小二乘拟合并立即生效
AT+RDFIT?             <- 查询：+RDFIT:<点数>,<SCALE‰>,<OFFSETmm>,<点1真值>,<点1原始>,...
```

拟合打印示例（官方基线数据）：`raw = 1.2006*true + 959mm` → `SCALE=833permille OFFSET=800mm`；
此时 0.5m 与 1.0m 都准确（官方单点偏移法在 0.5m 会剩 −10.1cm）。
**最多记 3 个点以上也支持**（`RL_FIT_MAX_POINTS=4`），多点会走最小二乘；`AT+RDTARE=<mm>` 仍可用于快速单点对零。

**v27 单点对零用法（保留）**：

```text
AT+RDTARE=760        <- 把当前测到的距离当作 760mm（会打印 [RL] tare ok: raw_med=... offset=...）
AT+RDTARE?           <- 查询，返回 +RDTARE:<原始中位数>,<当前偏移>
```

实测：发 `AT+RDTARE=760` 后 D 立刻由 ~750 变到 760，75 秒中位 798mm（σ≈10mm），0 复位。
**不需要重烧固件**；重新上电后偏移会回到默认（`CALIB_MM=994` + 开机自动对零 500mm），再发一次 `AT+RDTARE=<实际mm>` 即可。

## 2. 官方测距是怎么做的（研究结论摘要，详见研究文档）

- client（标签）连接后配置并使能 CS，把本端 IQ 经 SSAP 上传；server（锚点）与本端 IQ 配对（时间戳差 <20），
  调 `slem_alg_calc_smoothed_dis()` → ESPRIT + KDE 峰选 + Kalman，输出 `dis_smoothed`（米）。
- **官方唯一校准入口是 `calib_val`（float，单位米，库内从距离中减掉，平滑前生效）**；
  官方文档：1m 处 5 方向各测 5 次，**平均值减 1** 作为校准值，写入生效函数
  `slem_posalg_set_base_para()`（`sle_measure_dis_server_alg.c:32`；文档图指向的 `:59` 是死函数）。
- 官方默认：`ranging_method=4`（动态 r，79 信道，上限 150m）、`tof_calib=2070`、`r_start=2`、`threshold_cond2=20`。
  方法 2 会被库直接拒绝；TOF 在当前构建（未定义 `GLE_CS_MODE3_SUPPORT`）实际不参与。
- 输出字段：`D1=dist_first`（库平滑值，主输出）、`D2=dist_second`（未平滑候选值，诊断解模糊）、
  `PROB`（置信度，RSSI 好就高，**不能当精度指标**）、`SN`（平滑帧数，6 为收敛）。
- 库出错时输出 `-1.000` 模板帧，**必须丢弃**（我们已处理）。

## 3. 我们修了什么（都有实测/代码依据）

1. **校准模型纠错**：旧版 `SCALE=454‰/CALIB=303mm` 是错误拟合（导致 1m 读数 739mm，−26%）。
   现改为官方方法：`SCALE_PM=1000`、`CALIB_MM = 实测原始值(中位数) − 实际距离`。
2. **用户数据干扰**：实测 client 500ms 发用户数据会把 0.5m 原始值从 1583mm 拉到 1420mm；
   现默认周期 **5000ms**（`CONFIG_RANGE_LINK_USER_PERIOD_MS`），兼顾数据传输与测距精度。
3. **滤波/节流顺序**：旧版节流在滤波前导致窗口跨 4s、换位卡旧值；现每帧进滤波，节流只作用于打印/notify；
   增加连续野值重置。
4. **无效帧丢弃**（`dist_first < 0` 直接跳过）；**新增诊断字段** `D1/D2/PROB/SN`，便于现场复标。
5. **看门狗稳定性**（此前每 8~10s 复位）：SDK 只在 idle 钩子喂狗（`drivers/chips/bs2x/liteos/idle_config.c:36`），
   server 处理 CS/IQ 占满 CPU 饿死 idle → 任务内**每轮 `uapi_watchdog_kick()`** + 队列空时让步 1ms；
   队列 16 + 批量排空；回调打印静默；bt 栈加大。
6. **开机自动对零**（v25）：`RANGE_LINK_AUTO_TARE_MM`，开机取前 16 帧收敛样本中值算偏移，按复位即重对零。

## 4. 校准步骤（现场，官方方法）

1. 环境：3m 内空旷、无遮挡、天线平行同向、离地约 1m；client 数据周期保持默认 5s。
2. 两板按**最终使用距离**静置 ≥5s，等 `SN=6`，采 30 帧以上 `D1`（未校准原始值）取中位数 `M`。
3. 设 `CONFIG_RANGE_LINK_CALIB_SCALE_PM=1000`、`CONFIG_RANGE_LINK_CALIB_MM=M-实际mm`，重编译烧录
   （或直接用 `Tools/calibrate.ps1 -ActualMm <实际mm>` 一键完成采集→改常量→编译）。
4. 验证：该距离处 `D=` 应≈实际值。
5. 需要更远/更准可做多点拟合（用 D1 与真值线性回归得 SCALE/ CALIB），但注意原始值随环境/摆位漂移，
   **换环境建议重标**。

**我们的版本对比（同一环境尽力控制，仍受环境漂移影响）**：
| 版本 | 0.5m 读数 | 1.0m 读数 | 备注 |
|---|---|---|---|
| v12（旧校准 454‰/303mm） | 482mm（−18mm） | **739mm（−261mm，−26%）** | 校准模型错误，主因 |
| 官方固件 + 单点偏移（1m） | 399mm（−101mm） | 1000mm（0） | 说明 0.5m 存在近场/环境偏差 |
| v16（5000ms 数据 + 偏移 1073mm） | 545mm（+45mm） | 1148mm（+148mm） | 该会话原始值偏高（D1@1m≈2.2m） |

> 结论：**校准方法/常量是可控的主因**（v12 的 −26% 已消除）；剩余误差主要来自原始值随环境/摆位的 5~10% 漂移
> （同一 1m 不同会话 D1 从 2.07m 到 2.29m 波动）。要进一步提高，需在**最终使用环境**重标（或做分段/多点校准表），
> 这属于该芯片 SLE 相位测距的物理限制，不是代码 bug。

## 6. 已知限制

- **仅 1D 距离**，无坐标；坐标需 ≥3 块锚点 + 自研解算（本次需求已明确不做）。
- **原始距离抖动/漂移大**：同一 1m 位置在不同会话/摆位下官方算法原始值可从 2.07m 变到 3.2m（RSSI 也从 -55 变到 -67dBm），
  这是 SLE 相位测距在多径/近场/弱信号环境的固有限制（我们已对比：0.5m 处我们的原始值与纯官方固件一致，差 6mm，
  说明不是代码引入）。固件已做「未收敛帧丢弃 + 中值保持 + 弱信号丢帧」，能把**显示值**稳住，
  但**绝对准确度必须现场校准**，且不要在桌面多径/遮挡环境追求 cm 级。
- 校准是单点偏移，环境变化后必须重标（30 秒数据 + 改一个常量 + 重烧，或按复位让 v25 自动对零）。
- 用户数据与 CS 共用同一连接：周期太快会干扰测距（默认 5s）；数据为 best-effort。
- 测量频率在弱信号/门控下会下降（可能低至 0.1~0.3 次/秒）。
- SERVER 版 FLASH 约 95%（527KB/555KB），后续加功能注意体积。
