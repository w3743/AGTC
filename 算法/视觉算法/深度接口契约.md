# 深度数据接口契约

日期：2026-10-21（北京时间）  
状态：已用于接口实现，离线及集成验收中；数据接入就绪另行判定  
Schema：`depth-z-u16le-v1`

本文件是当前唯一的深度数据语义合同。维护方为“深度接口契约与评审”，板端实现方为“RK3588视觉与深度实现”，LASSC 消费桥由“训练方案与评测设计”维护，集成验收由“集成验收与证据复核”独立复核。它定义源深度、逐帧元数据、时间含义、重采样及旧策略适配语义；具体实现、部署和测试成绩以对应源码及运行证据为准。HTTP URL、封装与传输 framing 由 RK 候选 README 给出，并须引用本合同；不得在 README、实现说明或其他文档中另建一套数据语义。

## 源数据语义

| 项 | 合同值 |
|---|---|
| 坐标系 | 校正后的左相机光学坐标系：X 向右、Y 向下、Z 向前。`frame_id` 标识该坐标系。 |
| 深度 | 轴向 Z，不是相机到点的欧氏直线距离（range）。 |
| 数值编码 | `uint16` 小端毫米；图像逻辑形状为 H×W、C-contiguous、row-major，无行填充。对应 ROS 图像编码名 `16UC1`。 |
| 当前源图 | W=131、H=240，数组形状 `(240, 131)`；载荷长度严格为 `2×W×H = 62,880` 字节。 |
| 当前有效量程 | 300–5000 mm，端点均包含。这是版本化 profile 的范围，不能静默更改；当前旧策略上限为 5 m。 |
| 无效值 | 0。编码端对算法无效点写 0；解码端仍必须按范围防御性过滤。源 SGBM 不填洞。 |
| 有效性含义 | 有效代表通过当前算法筛选，不代表深度正确的概率或实物测距精度保证。 |
| 可视化 | JPEG/伪彩色仅用于显示，不能作为数值深度输入。 |

当前源 K 的 snapshot 参考值为 fx=147.487194、fy=147.487194、cx=65.766881、cy=121.086791。运行时每帧必须绑定实际源 K 和对应 calibration_id；这些参考数不能代替帧绑定标定。K 按 row-major 九个数表示：`[fx, 0, cx, 0, fy, cy, 0, 0, 1]`。

## 原子帧与 metadata

每一帧是一条不可变记录：metadata 与二进制载荷必须在同一锁保护下作为原子 snapshot 读取。HTTP 可以用不同封装传输 JSON metadata 和二进制载荷，但它们必须来自同一个 seq、pipeline_epoch 和同一 snapshot。禁止从全局 status 拼接旧图像，也禁止把两次请求中不匹配的 metadata 与图像当成一帧。URL、HTTP framing 和传输细节归 RK 候选 README；它们不能改变本节语义。

每条记录至少包含以下 metadata 字段。时间或标定值未知时使用 JSON `null`，不得用 0、当前处理时刻或静态猜测值伪装成观测值。

| 字段 | 含义 |
|---|---|
| `schema` | 固定为 `depth-z-u16le-v1`。 |
| `session_id` | 相机服务会话标识。 |
| `pipeline_epoch` | GStreamer running-time / clock mapping 的 epoch 标识；时钟会话变化时更新。 |
| `monotonic_clock_id` | Producer Python monotonic 时钟域及 boot/session 标识；只有该 ID 相同的 monotonic 值才可直接比较。 |
| `seq` | 帧序号；在同一 epoch 内单调递增。 |
| `width`, `height` | 当前 profile 固定为 131、240。 |
| `encoding`, `byte_order`, `unit` | 分别为 `16UC1`、`little`、`mm`。 |
| `convention`, `frame_id` | `convention` 固定为 `camera_z`；`frame_id` 单独标识 rectified-left optical 坐标系。坐标轴方向见“源数据语义”。 |
| `K` | 此帧、此载荷栅格对应的九个实际内参数，row-major；不是下采样策略 K。 |
| `calibration_id`, `extrinsics_id`, `preprocessing_id` | 标识产生本帧使用的标定、外参和预处理版本。未绑定外参时 `extrinsics_id=null`，不得虚构。 |
| `min_mm`, `max_mm` | 此帧所用 profile 的有效量程边界，当前为 300、5000；不是本帧观测到的最小值、最大值。 |
| `left_pts_ns`, `right_pts_ns` | 左右图像 PTS，单位 ns，来自共享 GStreamer pipeline running-time 时钟域。缺失时为 `null`。 |
| `source_time_reference` | 固定为 `left_pts`。 |
| `publish_mono_ns` | 原子发布该帧时的 Producer Python monotonic ns，时钟域由 `monotonic_clock_id` 标识；未知时为 `null`。 |
| `source_mono_ns` | 固定表示 `left_pts_ns` 经该 pipeline epoch 的 GStreamer PTS→Producer Python monotonic 映射得到的 ns。不能用配对到达、推理完成或发布时刻代替；映射或 PTS 未知时为 `null`。 |
| `clock_mapping_id`, `clock_quality` | 标识 `left_pts_ns`→Producer monotonic 的映射及其质量/可用状态；未知时为 `null`。 |

实现可以额外提供 `left_arrival_mono_ns`、`right_arrival_mono_ns`，表示左右帧到达软件的 Producer monotonic 时间，时钟域同样由 `monotonic_clock_id` 标识。这两个可选字段不等于曝光时刻，不能替代 `source_mono_ns`。`source_time_reference=left_pts` 仅统一参考时刻，不代表右帧同时曝光；必须保留左右 PTS 差。立体配对时效和容许偏差由性能与部署配置验证；当前约 25 ms 的软件配对容差不是验收目标。当前 PTS 属于共享 GStreamer pipeline running-time；实际曝光硬同步尚未验证。epoch 或时钟会话变化后，不得沿用旧映射。

metadata 的时间字段为 JSON 整数 ns 或 `null`。解码时必须保留整数精度，不得先经浮点数转换；若语言的默认 JSON parser 会丢失大整数精度，须使用能无损读取整数 token 的解析方式。即使 `source_mono_ns` 或 `extrinsics_id` 为 `null`，只要 schema、载荷和强制字段结构可解析，仍可报告“解析成功”；但必须报告 `legacy_ready=false`。不能因为格式正确便宣称部署数据接入就绪。

## 解码、有效性与策略张量

适配器必须先计算有效掩码，再做归一化：

~~~text
raw_valid = (mm != 0) & (300 <= mm) & (mm <= 5000)
valid = raw_valid & source_mask       # 若该 profile 提供 source_mask
z_m = mm * 0.001
policy_depth = where(valid, z_m / 5.0, 0.0)
~~~

uint16 wire payload 本身不能表示 NaN、Inf 或负数。Producer 在浮点深度量化为 uint16 之前，必须先将 NaN、Inf、负数、当前 profile 量程外的深度及算法无效点判为无效并写 0；禁止先 cast 成 uint16 导致溢出回绕。解码后的 0、1–299 mm、5001–65535 mm 以及 source_mask=false 的点均为策略无效值 0。若 producer/adapter 的量化前测试入口是浮点，应专门验证 NaN、Inf、负值与超 uint16 可表示范围的值均在 cast 前写 0。量程端点 300、5000 mm 有效。禁止先 clip 再把无效 0 变为 0.3 m。source_mask、筛选方法和量程属于版本化 profile；其语义变化须升级 profile/schema 并重新验收。

必须拒绝 schema 不符、宽高不符、载荷字节数不符、dtype/字节序不符及不符合 row-major 无填充布局的数据；不得静默 reshape、resize 或猜测字节序。adapter 内部要保留显式 `valid`，即使 legacy policy 只接收单通道深度。

旧策略输入兼容格式为 float32、CHW `(1,160,88)`；有效值为 `Z_m/5`，即约 0.06–1.0，无效值为 0。SB3 消费时不得再除以 255，也不在该兼容路径增加 CNN 通道。源帧有效掩码应在适配处理中保留，不得把归一化后数值非零当成唯一的源有效性证据。

## 到策略栅格的几何映射

现有策略目标栅格为 W=88、H=160，目标 K 为：

~~~text
K_t = [[98.3247958874, 0, 44],
       [0, 98.3247958874, 80],
       [0, 0, 1]]
~~~

此矩阵对应普通针孔相机经 USD 转换后主点居中的后端路径。`FieldTask.depth_intrinsics` 按像素中心缩放得到的构造前矩阵为 cx≈44.011254、cy≈80.557861；不能把它直接当作渲染后实际矩阵。现有环境把 `Camera.data.intrinsic_matrices` 写入深度帧，兼容旧检查点时应以其绑定训练后端和实际帧几何为准。适配器可以支持显式目标 K，但消费方必须记录其来源并验证，不能仅因形状同为 `(1,160,88)` 就切换采样矩阵。

同光轴、同外参条件下，目标像素按 K 映射至源栅格：

~~~text
u_s = fx_s / fx_t * (u_t - cx_t) + cx_s  ≈ 1.5*u_t - 0.233119
v_s = fy_s / fy_t * (v_t - cy_t) + cy_s  ≈ 1.5*v_t + 1.086791
~~~

这是基于源、目标 K 的射线对应关系，不是只按图像宽高缩放的保证。存在相机旋转时必须先做射线旋转再投影；存在不同光心平移时仅用 K remap 不能声称像素深度对齐。首个基线采用 nearest 取样，深度与 valid 必须使用同一索引；越界为缺测/无效，不补洞，不在前后景边界做双线性混合。像素中心和采样取整规则须由候选实现明确并由 fixture 固定；本合同不擅自规定 OpenCV round-ties 规则。

源图之外或源裁剪之外没有可恢复的图像信息。采样越界或无效时保留无效，不得通过邻点填充伪造覆盖。多尺度、ROI、双通道 D+M、远量程、保近障聚合和新 25–30 FPS 目标都属于独立实验，不自动变成旧模型效果承诺。88 像素宽、24 mm 茎、5 m 距离约 0.47 px 是几何估算，不是识别或导航能力结论。

## 时间、帧新鲜度与旧策略兼容

既有策略配置参考为控制步长 `dt=0.05 s`、depth period `0.4 s`、latency `0.3 s`；已有 `age_ratio=min(age/2 s, 1)`、newframe 和相对捕获位姿输入。`age` 必须使用 `left_pts_ns` 映射得到的 `source_mono_ns`，且 `consume_mono_ns` 必须在相同 `monotonic_clock_id` 时钟域。示例 source=1,000,000,000 ns、consume=1,250,000,000 ns 均在同一 clock_id 与 epoch，得 `age=0.25 s`、`age_ratio=0.125`。不得以 `publish_mono_ns` 或 arrival 时间替换源时刻。

若 consumer 在另一台 PC/host，只有在 producer→consumer monotonic clock 映射经过验证、并给出误差界后，才可先转换到同一时钟域计算 age；仅 pipeline_epoch 相同不够。没有已验证映射及误差界时 `legacy_ready=false`。负 age、future source time、同一 `monotonic_clock_id` 内时钟倒退或映射回归必须拒绝该帧或标记 unready；不得把负值 clip 成 0 来伪装 fresh。PTS→producer monotonic 映射缺失或 epoch 不一致时也不能计算可靠 age。

旧策略中的相对采集位姿和云台变化必须对应映射后的源时刻。适配器可从另一路遥测历史查询或插值该时刻的估计位姿及实测云台反馈，无须在深度载荷中复制遥测。缺少对应时刻的记录时，不能用发布时或当前位姿回填，也不能用动作指令冒充实测反馈；相关观测未满足部署配置时保持 `legacy_ready=false`。

消费者只使用最新完整帧。重复 seq 不得冒充 newframe；更旧的乱序 seq 必须丢弃或拒绝并有 fixture 覆盖。epoch 变化时明确重置序号跟踪和时钟映射，不把新 epoch 的帧与旧 epoch 的时刻相减。模型状态何时切换由部署策略另行确定，本契约不擅自规定。

`legacy_ready` 是 adapter/deployment 按目标部署配置作出的派生就绪判断，不可盲信生产者自报。至少要求 schema、shape、encoding、profile 通过校验；K 为真实帧绑定有效 K 且 calibration_id/preprocessing_id 可识别；使用的坐标变换有有效 extrinsics_id；age 相关输入有同 epoch 的 source_mono_ns、clock_mapping_id、可用 clock_quality 及匹配的 monotonic_clock_id。跨 host 时还须有已验证时钟映射和误差界。任何必需项缺失都报告缺项并保持 `legacy_ready=false`，同时允许单独报告“载荷可解析”。系统端到端年龄上限由性能/部署 owner 确定；历史 1.5 s 拒绝阈值不是安全目标。`legacy_ready` 仅表示满足部署配置的数据接入要求，不表示硬件安全、感知正确或导航能力。

## 纯离线验收 fixture

以下是实现必须满足的固定验收输入与预期；测试已复用既有套件并补充跨层缺口，具体成绩及源码快照以[本轮执行证据](软件/数值深度接口候选/evidence/contract_acceptance_20261021/)为准。fixture 能核验确定性格式和逻辑；不能证明真实测距精度、曝光同步、全链延迟或导航能力。

| # | 输入 | 预期 |
|---:|---|---|
| 1 | Codec 单元 fixture 按 row-major 输入 uint16 值 `[0, 300, 1000, 5000]`；此四值片段不是合法的 131×240 全帧。 | 小端字节严格为 `00 00 2c 01 e8 03 88 13`；解码回原值。用已知非对称值与位置锁定 codec 字节序/坐标约定。 |
| 2 | 输入 `[0, 299, 300, 1000, 5000, 5001]` mm。 | `valid=[0,0,1,1,1,0]`；归一化为 `[0,0,0.06,0.2,1,0]`。端点有效，越界和 0 不被 clip 成 0.3 m。 |
| 3 | 上例中给 1000 mm 像素设置 `source_mask=false`。 | 该点最终 invalid 且策略值为 0；正深度不能覆盖 source mask。 |
| 4 | 并发发布完整 A/seq=10 与 B/seq=11 帧，读者重复获取 snapshot。 | 每次读到的 header 与 payload 都属于同一 A 或 B；从不出现 A header+B payload、部分载荷或混搭 epoch。 |
| 5 | 提供少/多字节、metadata 声明的 encoding/endian 与合同不符、metadata 宽高交换、metadata 显式声明 padding 等帧；另用非方形非对称像素图通过 codec。 | 可由 header/长度检查发现的声明错误显式拒绝；非对称 codec fixture 解码到预期值和坐标。若 payload 字节错误却谎报 little，或逻辑转置/填充却谎报 row-major，仅靠 header 无法普遍识别；不得声称 decoder 能普遍检测。 |
| 6 | 常量 Z、checkerboard、内部 invalid 与越界 remap 输入；再分别给 K 非有限/非法、K 与绑定 calibration 不一致，或未知 schema。 | nearest 映射下 Z 与 valid 同索引，边界不混前后景，越界/无效保持无效且不填洞；非法/不一致 K 或未知 schema 的帧拒绝进入 legacy tensor。其他合法且与 snapshot 参考值不同的帧绑定 K 不应仅因数值不同而拒绝。 |
| 7 | 同 epoch、同 `monotonic_clock_id`：source=1,000,000,000 ns，publish=1,100,000,000 ns，consume=1,250,000,000 ns。 | age=0.25 s、age_ratio=0.125；不得用 publish 计算成 0.15 s。 |
| 8 | 首次 seq=10，随后再次 seq=10，再收到 seq=9；之后 pipeline_epoch 改变并按新 epoch 初始化。 | 重复 seq 的 newframe=false；较旧 seq=9 丢弃或拒绝；新 epoch 重置序号追踪和映射，不能跨 epoch 比较时刻。 |
| 9 | pipeline_epoch 相同，但 source 属于 Producer monotonic_clock_id=A，consume 属于另一 host 的 monotonic_clock_id=B。 | 不直接相减；只有经验证的 producer→consumer 时钟映射及误差界将二者转换到同域后才计算 age，否则 `legacy_ready=false`。 |
| 10 | 检查 legacy 输出 shape、dtype、范围及有效位。 | 严格为 float32 `(1,160,88)`；无效全为 0，有效仅 0.06–1.0 且有限；SB3 路径无二次 `/255`，无额外 mask CNN 通道。 |
| 11 | `source_mono_ns`/`clock_mapping_id` 缺失或 `extrinsics_id=null`；另测 source time 晚于 consume、同 monotonic_clock_id 时钟倒退/映射回归。 | 可报告 schema/载荷解析成功并逐项报告 readiness 缺失，`legacy_ready=false`；future/回归帧拒绝或 unready，不把负 age clip 成 0、不冒充 fresh。 |
| 12 | 构造当前 crop/栅格边界外的目标射线以及裁剪前但已不在 131×240 源图中的区域。 | 越界保持缺测/invalid，不从邻点填补，不声称恢复裁剪外像素。 |

## 可执行验收入口

在 `软件/数值深度接口候选/` 目录运行以下命令。完整套件复用既有 producer、HTTP、adapter 测试，并包含[跨层验收](软件/数值深度接口候选/tests/test_depth_contract_acceptance.py)与[未来坏帧回归](软件/数值深度接口候选/tests/test_depth_adapter.py)。纯 consumer 命令只选择四项真实 LASSC 桥接测试，不加载 producer 的 OpenCV 依赖。

~~~powershell
python -B -m unittest discover -s tests -v
python -B -m unittest discover -s tests -p test_depth_contract_acceptance.py -k lassc -v
~~~

运行退出码、实际测试数和被测源码前后 SHA 分别保存在[完整套件结果](软件/数值深度接口候选/evidence/contract_acceptance_20261021/full_suite_final_result.json)和[纯 consumer 结果](软件/数值深度接口候选/evidence/contract_acceptance_20261021/consumer_only_final_result.json)；[覆盖对应表](软件/数值深度接口候选/evidence/contract_acceptance_20261021/coverage_map.json)将本契约十二项条件对应到该快照日志中实际通过的测试。跨层测试使用显式合成输入，调用生产实现；其中 LASSC 事务测试设 `runner=None`，实际检查点推理和 LSTM 验收由独立集成回放承担。
