# 活动保留系数实验

## 研究问题

检验在同一网络宽度、数据流、训练步数和更新次数下，为隐藏活动增加显式保留系数，是否改变在线 RTRL 的预测表现与计算/状态灵敏度预算。该设计比较三种配置：

1. `baseline_rtrl20`：基线 Streaming RTRL，隐藏活动直接取候选值 `h=candidate`。
2. `fixed_activity20`：每个神经元使用常量 `a=0.5`。
3. `learned_activity20`：每个神经元具有独立可学习 logit，`a=sigmoid(logit)`。

活动更新为 `h = a*h_prev + (1-a)*candidate`。固定和可学习方案分别有851和871个训练参数，RTRL核心灵敏度分别有641和661维。`a` 是隐藏状态更新系数，不是由输入计算的门。快速连接矩阵 `F` 仍按基线 `r` 痕迹公式递推，仅将其中的隐藏状态替换为新 `h`。

## 实验协议

- 方案：`baseline_rtrl20`、`fixed_activity20`、`learned_activity20`。
- 任务：交替 `01`、三连 `000111`、周期16 `0000100110101111`。
- 种子：`2`、`20261027`、`20261028`。
- 每个任务序列长600；合计3×3×3=27次运行、16,200次预测。首位输入没有可用的历史输入状态，因此不更新参数；每次运行共599次更新。
- 学习率0.015，Adam普通参数 weight decay 为1e-4；`r` 和 `a` 参数 weight decay 为0；全局梯度裁剪阈值1；输入权重每次更新后的软阈值收缩系数0.02。其他网络结构、输入输出接口和 RTRL 规则按对应实验实现记录。
- 结果文件：`aggregate.json`（每方案×任务汇总）、`runs_summary.json`（逐运行摘要）、每个运行目录的 `events.jsonl`、`compute_profile.json` 和 `audit.json`。`runs_summary.csv` 由主 runner 生成。
- 报告入口：`python report_activity_retention.py <RUN_ROOT>`。入口读取正式运行根目录的数据，生成离线 `report.html` 与 PNG/SVG 图表；图表以 data URI 内嵌在 HTML 中。

## 机制与资源解释

基线模型保留既有 `r` 痕迹更新。活动保留方案在候选活动和前一时刻活动之间插值，并在 RTRL 灵敏度递推中传播 `a` 的影响。可学习方案把活动系数的任务梯度纳入核心参数梯度；固定方案将其保持在0.5。`r` 与 `a` 不接受 weight decay，其余训练设置保持相同。

三种方案有相同的600步序列与599次更新，但算术工作量、核心灵敏度规模和参数量不完全相同。因此准确率对照是同更新数对照，不是同算力或同参数量对照。`compute_profile.json` 中的 proxy 是该实验定义的计算代理，不等同硬件 FLOPs；eligibility 字节仅为 float32 灵敏度张量的理论存储量，不含模型、优化器和其他状态。CPU均值/中位数受设备、线程和测量环境影响。

## 结果报告限制

每个方案×任务只有三个随机种子，种子范围只能作描述性观察。50步窗口学习曲线展示的是观察到的预测命中率；它不构成显著性检验。活动保留系数上升只表示更新时更偏向前一时刻状态，不能单独证明有用记忆增加。应结合任务成绩、NLL、`r`/`a` 分布、梯度和预算审慎解读。

审计状态必须来自运行根目录真实的 `audit.json` 中 `passed` 字段。缺少该文件或 `passed` 不为 `true` 时，HTML 将明确标为尚未通过/尚未完成，不得宣称实验通过审计。HTML 的关键摘要从 `aggregate.json` 动态计算固定/可学习方案相对基线及 learned 相对 fixed 的逐任务准确率百分点差和平均NLL差，不预设方向。

## 本轮结果

数据来自 `C:/pioneer/rnn-research-runs/activity_retention_20261031/run_20261031T023713_840581Z`。27次运行已完成，共16,200次预测；每方案×任务合并三个种子，每格1,800个预测。

| 任务 | 基线准确率 / NLL | fixed 准确率 / NLL | learned 准确率 / NLL |
| --- | ---: | ---: | ---: |
| 交替 | 99.56% / 0.0336 | 88.78% / 0.2232 | 91.11% / 0.1722 |
| 三连 | 87.11% / 0.1816 | 33.39% / 0.7587 | 37.28% / 0.7391 |
| 周期16 | 43.94% / 0.8121 | 39.22% / 0.8055 | 39.61% / 0.8168 |

该结果不支持活动保留改动改善基线：fixed 和 learned 在三个任务的准确率都低于 baseline。以各任务等样本数合并，baseline 为76.87%，fixed 为53.80%（低23.07个百分点），learned 为56.00%（低20.87个百分点）。learned 相对 fixed 的准确率分别高2.33、3.89、0.39个百分点，但仍未赶上基线；其周期16 NLL也略高于基线。因而 learned 相对 fixed 的小幅优势不能解释为活动保留机制相对原 RTRL 有效。三个种子样本有限，以上是描述性结果。

learned 最终活动系数 `a` 在三个种子×20个神经元上的均值与全体元素范围：交替0.3165 [0.0297, 0.5202]；三连0.4458 [0.1537, 0.6539]；周期16 0.4791 [0.4221, 0.6066]。learned 每项任务的1,797次更新中，a 梯度均为1,797次非零。该梯度活动与系数变化说明参数确实参与学习，但不代表学到的保留系数带来了有用预测收益。

三连任务的种子差异值得单独披露：seed 20261028 下，fixed 为9/600（1.50%），末100步0%；learned 为79/600（13.17%），末100步70%。其余两个种子中，两方案准确率都约49%。该单种子差异不能代表稳健收益，也不改变learned三连总体37.28%低于基线87.11%的判断。

计算预算方面，profile 记录的完整运行算术代理分别为 baseline 1,906,187,965、fixed 1,929,347,326、learned 1,989,372,023；灵敏度元素数分别为269,220、269,220、277,620，float32 理论字节分别为1,076,880、1,076,880、1,110,480。串行单线程均值/中位数（毫秒）为 baseline 2.089/1.994、fixed 2.436/2.312、learned 3.336/3.117。proxy不是硬件 FLOPs，单线程测量不构成普适性能保证。

独立审计现已通过：`audit.json` 覆核17个源码来源、268个原始文件哈希、189个检查点、16,200条新运行事件、5,400条旧基线事件、540个冻结前缀事件及9项预算计数；`frozen_unit_validation.json` 的6项检查也通过。审计通过只说明所列数据与机制核验通过，不改变本轮准确率相对基线下降的结果，也不构成对其他任务或配置的推广结论。
