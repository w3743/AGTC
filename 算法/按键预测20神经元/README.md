# 按键预测 20 神经元

这是一个固定 20 个活动单元的本地在线训练原型。用户每按一次 0–9，服务先用先前封存的预测计分并写入记录，再把新数字作为答案学习，随后读取这个数字并生成下一次预测。新版使用 UORO 近似在线梯度、持续的活动与连接边迹，以及自适应稀疏输入；旧版窗口训练保留为对照。它是一个可塑 RNN 起点，不声称已经自动发现或验证了通用学习算法。

## 运行

项目默认使用已安装 CPU 版 PyTorch 的环境：

```powershell
& 'C:\pioneer\mnist-local-neuron-env\Scripts\python.exe' '.\server.py' --host localhost --port 8765
```

也可用启动脚本：

```powershell
& '.\start.ps1'
```

脚本默认 Python 路径为 `C:\pioneer\mnist-local-neuron-env\Scripts\python.exe`，可通过 `-Python` 指定其他解释器：

```powershell
& '.\start.ps1' -Python 'C:\path\to\venv\Scripts\python.exe' -Port 8765
```

若需新建 Python 环境，先安装依赖：

```powershell
python -m venv .venv
& '.\.venv\Scripts\python.exe' -m pip install --index-url https://download.pytorch.org/whl/cpu -r '.\requirements.txt'
& '.\.venv\Scripts\python.exe' '.\server.py' --host localhost --port 8765
```

`requirements.txt` 固定 PyTorch `2.14.1`；项目运行环境已验证为 `2.14.1+cpu`。

服务只监听 `127.0.0.1`，`--host` 只接受 `localhost`。网页由相邻的 `dist/` 目录提供；API 可单独使用。默认端口是 `8765`。

默认 `--mode uoro`，UORO 默认配置为 rank 4、学习率 `0.003`、输入权重收缩强度 `λ=0.02`，并启用最近一次转移的精确求导。可配置 `--uoro-rank`、`--learning-rate` 和 `--input-sparsity`；具体值写入每次运行的清单。`--input-sparsity 0` 关闭输入收缩，供实验对照使用。`--mode window` 运行旧版最近 32 个数字重放模型。

数据写在版本库外。默认每次启动都会在 `C:\pioneer\local-neuron-runs\` 下创建唯一的 `keypress20_<时间>_<随机后缀>` 目录；传入 `--data-root` 可更换其父目录。每个会话有独立 UUID 子目录。按“重开会话”会创建新子目录，不清除旧日志；重启进程也会创建一轮全新的模型和 run 目录。

## 模型与训练

输入端口是 10 个数字的 one-hot 向量，不计入 20 个神经元。每一步读取旧活动 `h` 和旧边迹 `F`，按以下公式更新活动：

```text
h' = tanh(Win · x_digit + (Wrec + eta · F) · h + b)
```

`Wrec` 是完整的 `20 × 20` 有向矩阵。矩阵行是目标单元、列是来源单元，因此 `connections[i][j]` 表示从单元 `j` 到单元 `i` 的连接。没有出边数量上限。活动更新后，局部边迹按来源/目标活动更新：

```text
F' = decay · F + (1 - decay) · outer(h', h)
```

`eta` 与 `decay` 是共享可训练标量。输出端口直接取前 10 个活动值乘以一个共享正比例作为 logits，再做 softmax；模型没有额外的 10 个读出单元。

### UORO 持续状态模式

活动 `h` 和边迹 `F` 在同一会话内跨按键持续保留。每个新数字只提供一个新的监督答案，不进行历史窗口重放、不在第 32 步清空状态。第一键只有输入、没有已观察的相邻转移；从第二键起，每键执行一次参数更新，再用新参数和保留的旧状态读取这个新数字。没有可训练转移对时，界面预测保持均匀分布；并列 top-1 取数字 0。

UORO 为状态对参数的敏感度维护若干组低秩随机估计，每组由两个向量组成，而不分配完整影响矩阵。当前状态有 20 个活动和 400 个边迹，参数仍为 623 个，因此一组核心估计包含 `420 + 623` 个数。随机性用于估计训练梯度，模型连接依照预测误差更新。增加独立估计组数可减少噪声，也会增加计算和内存。

默认精确求导最近一次输入转移，较早的影响仍用 UORO 估计，以减少最新输入训练信号的噪声。这只缓存一个已发生输入及其转移前状态、参数和低秩系数，不截断更早信用，也不增加神经网络的内部传播步数。`exact_readout_step=False` 可在模型级对照中关闭。rank 4 时，当前因子占 16,688 字节；有待评分预测时，额外转移缓存占 20,860 字节（其中包含另一份因子），不含 PyTorch、模型参数、优化器和临时导数空间。

这不保证无限或无损记忆。活动动力学仍可能遗忘，低秩估计可能有很大方差；逐步更新参数、梯度裁剪和后述收缩也意味着不能将整套算法称为精确全历史梯度下降。参考 [UORO 原论文](https://arxiv.org/abs/1702.05043)。

### 自适应稀疏输入

输入权重仍是 `20 × 10` 的可训练候选矩阵。每个数字使用自己的权重列，因此可学出不同、可重叠的接收子集。每次参数更新后，对输入权重执行向零收缩，小权重成为精确零；没有 top-k 或固定连接数量。零权重仍保留在候选计算图中，之后有足够数据梯度时可以重新非零。这里实现的是 Adam 后的收缩步骤，稀疏力度需要与学习效果一同验证。

零输入权重意味着对应神经元没有来自该数字的直接输入贡献；这与循环连接的可视化阈值不同。候选矩阵仍然存储和参与训练，当前实现不承诺稀疏硬件加速，也不改变内部 400 条循环候选连接。由于网络每读一个数字只传播一步，入口变少可能影响最新数字到读出端的传播，实验需要检查这种取舍。

### 旧版窗口模式

`--mode window` 使用最近最多 32 个已发生的数字构成相邻预测对，每键做 3 次 Adam 更新。训练和预测从零重放这一上下文。超过 32 步的活动上下文不进入当次重放；已学习的参数和优化器仍持续保留。`model.py` 保存该基线实现，`online_model.py` 实现新的在线模式。

## 2026-10-27 首测摘要

最终首测采用 rank 4、学习率 `0.003`、默认 `λ=0.02`、最近一次转移精确求导的持续状态 UORO。主试验每个序列运行 600 键、两个模型 seed，并同时检查 `λ=0` 对照，共 12 runs、7,200 次预测。以下是两个 seed 的整体 top-1 准确率范围：

| 序列 | `λ=0` | 默认 `λ=0.02` |
|---|---:|---:|
| `0..9` 循环 | 72.83–84.00% | 72.83–78.00% |
| `000111...999` 三连循环 | 30.00–32.33% | 23.67–34.00% |
| 随机数字 | 9.50–10.00% | 9.50–10.50% |

默认收缩强度下，每次运行结束仍有 199–200 条非零输入权重（共 200 条候选），目前几乎没有形成稀疏矩阵。更强的 `λ=0.1` 两 seed 探针留下 183 和 188 条非零输入权重；三连循环准确率为 24.00% 和 25.33%，没有显示稳定改进。

同日窗口重放基线的 `0..9` 循环为 98.00–98.33%，三连循环为 87.33–90.83%。这不能作为公平的算法排名：窗口基线学习率为 `0.015`，每键最多做 3 次更新、每次重放不超过 31 个历史转移；UORO 学习率为 `0.003`，每个新转移只更新一次（首键没有前序转移，因此不更新）。

8 类提示记忆探针的每个 episode 输入 `8, cue, N 个均匀随机干扰数字, 9, cue`；预测并评分 `9` 后的最后一个 cue，查询前没有再次提示 cue。模型状态跨 episode 保留，不重置，也不对查询额外加权。每个延迟、每个 seed 各有 100 次查询：8 个干扰数字后的准确率为 10–11%，40 个干扰数字后为 12%，条件随机基线为 12.5%。零状态固定参数的 cue 对照探针每个 seed 命中 8/64（12.5%）。这些结果没有显示高于基线的延迟记忆能力，也不验证一般或无限记忆。

模型测试 6 项、服务测试 2 项通过；短序列 256-trial Monte Carlo 检查与精确梯度的相对误差为 `0.05581`、余弦相似度为 `0.998446`，只验证梯度估计的数值行为。桌面浏览器验收已通过；本轮未测移动端。详细协议、限制和证据路径见同目录的 `验证记录.md`。

## 2026-10-27 单变量对照

为定位新版命中率下降，又进行了 11 组、3 个配对初始种子（`2`、`20261027`、`20261028`）、2 种序列、每次 600 键的实验，共 66 runs、39,600 次预测。seed 2 对应作为复现对象的那轮 57 键会话的初始化；新版前 57 次的概率逐项复现用户记录中的 17/57。各组初始参数逐位相同，源码、序列、优化器配置与逐键记录均已冻结；正式运行全部完成，无失败。

下面每一行只比较所列条件下的一项变化，数字为三个种子的整体命中率均值。各行的起点不同，不能把它们当成同一个基线上的独立贡献：

| 单项变化 | `0..9` 循环 | 三连循环 |
|---|---:|---:|
| 旧版参考只增加输入收缩 `λ=0.02` | 98.22% → 98.22% | 89.94% → 89.44% |
| 每键更新 3 次 → 1 次，仍训练多个历史答案 | 98.22% → 98.00% | 89.94% → 85.83% |
| 每键一次更新，多个历史答案联合纠偏 → 只训练最新答案 | 98.00% → 97.44% | 85.83% → 64.44% |
| 上一组学习率 `0.015` → `0.003` | 97.44% → 94.94% | 64.44% → 58.11% |
| 持续状态、单个新答案、相同优化器，完整精确在线敏感度 → rank-4 UORO | 84.83% → 62.72% | 57.83% → 29.83% |

当前配置的主要问题出现在训练目标从多个历史答案变成单个最新答案，以及使用 UORO 近似较早影响这两个环节。较小学习率还拖慢了顺序任务的早期学习：三个种子前 57 键的平均命中率从 73.10% 降至 54.39%。只减少每键更新次数没有造成当前版本同量级的下降。

输入收缩在旧版参考的顺序任务中把输入连接从 200 条减少到 131–133 条，仍保持 98.22% 命中率。因此，本轮强度下的输入稀疏不是主要退步原因；这不保证任意程度的稀疏都无损。

持续状态也需要稳定的训练影响追踪。保留持续状态、只精确追踪最近 32 次转移影响的参考，顺序任务三个种子的最后 100 键均为 100%；完整历史敏感度参考有一个种子在后期退化到 30%，同时出现活动饱和和近乎均匀的输出。这里的 32 只是诊断用的梯度追踪范围，不会清空前向记忆；此实验没有把生产模型改回固定窗口。精确参考不对 Adam 更新历史求导，也不是大规模网络的低资源替代方案。

`ablation_window.py`、`ablation_reference.py` 和 `run_ablation.py` 只用于隔离实验，不改变网页模型。全部 11 组、10 条对照边、每个种子和末段成绩，以及独立复算记录见 `验证记录.md`。

可在新的数据父目录复现实验；程序会创建唯一的 run 子目录：

```powershell
& 'C:\pioneer\mnist-local-neuron-env\Scripts\python.exe' '.\test_ablation_reference.py'
& 'C:\pioneer\mnist-local-neuron-env\Scripts\python.exe' '.\run_ablation.py' --groups all --seeds 2 20261027 20261028 --sequences cycle triple --steps 600 --data-root 'C:\pioneer\local-neuron-runs\uoro_ablation_repeat'
```

## 实时结构图

主界面的结构图显示固定 20 个神经元及其有向循环连接。节点位置仅用于排布，不代表网络分层；第 1–10 个神经元同时对应数字 0–9 的输出端口。

节点颜色按固定的 `[-1, 1]` 活动范围显示正负方向，颜色深浅表示绝对值大小。每次输入完成后，图与本轮训练后的活动、连接权重和按键步数同步更新；没有新输入时模型状态保持不变。图展示当前状态快照，不展示展开计算中每一步的传播动画。

连接箭头从来源神经元指向目标神经元，权重使用 API 返回的有效连接 `Wrec + eta * F`。连接筛选只影响图中显示，模型仍保留完整的 `20 × 20` 连接。选中节点可查看活动数值及与其有关的连接。

窄屏默认显示完整结构图；点击“放大查看”可横向浏览放大的节点和连接，点击“显示全图”恢复总览。

仅前端文件更新时刷新页面即可加载新版界面。切换模型实现或训练模式后需要重启服务；重启会开始新的 run/session，已有记录仍保留在各自目录。

## API

- `GET /api/state` 返回当前会话、封存预测 ID、概率、预测来源、准确率指标、20 个活动、`20 × 20` 循环连接矩阵、最近 30 个历史数字，以及上一条 `last_result`。新增 `training_mode`、`model_info` 诊断、`input_connections[20][10]` 输入权重、`input_counts[10]` 精确非零数量、`recent_hit_counts` 最近 30／90 次命中统计。输入矩阵行为目标神经元、列为数字入口；循环矩阵行为目标、列为来源神经元。
- `POST /api/press` 接收 JSON `{"digit": 0, "prediction_id": "..."}`。`digit` 必须是 JSON 整数且严格在 0–9 内；布尔值、浮点、字符串均会拒绝。成功响应包含新的 state 和被消费预测对应的 `last_result`。同一预测 ID 只能消费一次；过期或重复 ID 返回 HTTP 409，错误形如 `{"error":{"code":"stale_prediction","message":"..."}}`。请求体上限为 4096 字节。
- `POST /api/reset` 可不带 body 或发送 `{}`，创建全新的会话与模型状态，旧日志仍留在 run 目录。
- `GET /api/export` 下载 `application/json` 文件，包含 run 下所有会话清单及 JSONL 事件。

错误统一使用 `{"error":{"code":"...","message":"..."}}`。HTTP API 的 JSON 响应不缓存。

## 记录与范围

每次启动会在 run 目录中保存 `source_snapshot/`，逐字节复制模型、服务、依赖清单、README、启动脚本和可用的 `dist/` 文件，并写入包含各文件 SHA-256 的清单。run 与会话清单还记录配置 SHA-256、Python/PyTorch 版本和线程数。`events.jsonl` 每次按键写两条按 `session_id` 与步骤关联的记录：第一条在历史更新前保存封存概率、选择、实际数字和得分；第二条在训练完成后保存训练耗时、可塑参数值和下一预测、活动与连接。这种顺序便于重放核对计分没有使用当前真实数字重算。

每次按键训练和新预测完成后，会把模型、Adam 状态、最近显示历史、计数、封存的下一预测等写入 `latest_checkpoint.pt.tmp`，完成后通过同目录原子替换更新 `latest_checkpoint.pt`。在线模式另含 `model_checkpoint_state`，完整保存其持续状态、UORO 系数及 RNG。模型类提供检查点载入接口，供模型级确定性续接验证；服务程序重启仍从新 session 开始。

`events.jsonl` 和清单会保留；当前服务不自动恢复训练检查点，停止后重新运行会开始新的 run。在线模式的检查点包含持续活动、边迹、UORO 系数和随机数状态，供完整审计和模型级续接验证。准确率是本模型 top-1 的累计准确率；最近 30／90 次指标只用于显示成绩，不限制模型记忆。随机基线固定为 10%，多数类基线每次只根据当时以前输入的数字计算，平票选最低数字。
