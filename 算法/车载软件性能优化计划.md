## 首项：深度编码原生候选

[native](视觉算法/软件/数值深度接口候选/native/)提供独立 C++ float32/float64 深度毫米编码候选，以及离线差分测试和微基准。它尚未接入视觉服务，不能替代完整的服务迁移；现有 Python 编码器接受的其他输入类型、形状校验和其余 wire/元数据契约也尚未由该接口覆盖。调用方必须保证缓冲区不重叠和行优先连续输入；不得使用会破坏 NaN 检查或精度语义的 fast-math 构建选项。源码对 GCC 可检测的 `-ffast-math` 和 `-ffinite-math-only` 设置编译期拒绝，两项拒绝路径已在主机核验；其他编译器的等价选项仍须核查。

2026-11-13 主机检查：`python -B .../native/test_depth_encode.py` 两项通过，float32 和 float64 各以约 20 万个随机值、量程、非有限数及各毫米舍入中点和相邻值与 Python 结果逐字节对照；无效指针及容量也做了检查。仅为主机测试，并非完整穷举。

同日主机微基准：Windows 10.0.26300、Intel64 Family 6 Model 198、Python 3.11.9、NumPy 2.4.6、g++ `-O3`，固定种子生成 240×131 float32 深度，含每七项一个 NaN，预热 50 次，分别测量 1000 次。最初原生候选中位数为 197.1 µs、同期 Python 为 161.7 µs；调整循环后，Python 中位/P95/P99 为 159.5/232.7/329.1 µs，C++ 候选为 138.6/165.3/215.7 µs，中位数低约 13%。C++ 使用预分配输出，Python 每次创建输出字节，因此接口成本并不完全相同。脚本可复现测量方式，结果随负载变化；未监控频率、温度或功耗，不是严格可比的板端性能证据。**尚未接入完整服务或在板端测试，不应部署替代现有服务。**

下一步：分析目标板真实数据分布与编码占整个采集、计算、传输链的比例，改进原生实现并进行等价测试；在 RK3588 同配置下测量端到端及热稳态，完善构建和服务集成后再进行迁移验收。2026-11-13 `adb devices -l` 未列出设备，当前板端源码版本、资源占用和真实性能均未核验。

## 深度缓存并发逻辑原生候选

[depth_store](视觉算法/软件/数值深度接口候选/native/depth_store.h) 是独立 C++ 候选：有界历史、不可变共享帧、等待指定序列或新鲜帧、管线代次及标定代次失效。管线切换、标定状态或几何有效性变化时，等待请求被唤醒，旧计算令牌不得发布；过期和未来时间戳不能作为 latest，指定序列可读取历史帧。与现有服务相比，候选对标定代次或几何状态在等待期间变化采用更保守的失效处理，集成前须核对调用链和 HTTP 状态、消息与唤醒行为。

本机用 g++ 16.2.0 `-O2 -Wall -Wextra -Werror -pthread` 编译运行并通过，另用 CMake Release 构建和 CTest 通过（1/1）；测试覆盖无设备、历史淘汰、旧快照、陈旧/未来帧、等待新帧、切换唤醒、过期令牌、标定和几何失效。测试使用合成帧和主机时钟，不覆盖真实相机、HTTP 服务、标定计算、实际调度或目标板性能。候选调用者须使用与 C++ `steady_clock` 同一时钟域的发布时刻并验证时钟映射，且负责元数据校验及网络响应；它尚未接入服务，也没有声称现有 Python 服务已迁移。

用户说明无法提供 RK3588。离线开发可继续；目标板构建、实际部署、真实性能及整车验收仍待设备与对应工况可用，不能用主机结果替代。

## 原生深度发布与读取候选

[depth_producer](视觉算法/软件/数值深度接口候选/native/depth_producer.h) 将 131×240 float32 深度编码为现有 little-endian 毫米格式，构造必要的 ASCII JSON 元数据，连同序号、管线代次和单调时钟时间在缓存中一起发布。[depth_request](视觉算法/软件/数值深度接口候选/native/depth_request.h) 对已经由 HTTP 解析器解码的 `sequence` 参数做范围检查，并将读取结果映射至 200、400、409 或 503；返回帧使用同一不可变快照。元数据字符串当前仅接受可打印 ASCII，拒绝控制符；相机内参和时间字段做基本校验。调用方仍须确保序号跨并发发布唯一递增、时钟域和几何证据真实；不可直接用未经校验的 `DepthStore::publish` 接收外部帧。

主机 CMake Release 构建和 CTest 3/3 通过；独立 `python -B native/test_depth_pipeline.py` 编译运行 C++ 合成发布链，并用现有 Python wire 解码器核验元数据、超过 2^53 的时间戳、无效值与完整载荷，1 项通过。测试还核查无效请求、缓存未命中、过期令牌和头部控制符拒绝。当前只支持有效 wire 记录，尚未覆盖旧服务中有测量历史但没有 wire 记录的状态；没有 GStreamer 相机、SGBM、标定、监控和页面接入，也没有真实设备或完整服务的性能结果。此候选尚不能替代在线 Python 服务，后续须完成端到端集成与同等工况测试。

## HTTP 深度响应候选

[depth_http](视觉算法/软件/数值深度接口候选/native/depth_http.h) 处理 `/depth.bin` 的 GET 目标、解码和核查序号参数，生成 HTTP 状态行、必要响应头和错误 JSON，成功时持有原有不可变帧，避免为响应体再复制一份。它拒绝带控制字符的头及无效载荷长度；百分号编码错误等非法请求的处理比旧服务更严格。该模块本身不负责 TCP 连接、方法与 HTTP 报文解析、并发或超时限制，必须由完整服务器正确实现这些功能。

`test_depth_http.py` 编译仅绑定本机回环的测试夹具，经 TCP 发送请求，再由现有 `DepthProbeCollector` 检查成功响应的内容类型、长度、no-store、元数据和载荷；同时验证指定序号、重复参数、非法编码、缺帧和其他路径。测试通过。C++ 单元测试还覆盖陈旧 latest、历史帧、超长目标、错误长度与头注入拒绝。夹具是测试程序，不是可部署服务器；合成帧不代表相机工作，未进行网络吞吐、时延、并发或板端测量。

## SGBM 深度过滤候选

[depth_filter](视觉算法/软件/数值深度接口候选/native/depth_filter.h) 将现有 SGBM 视差的窗口支持、深度换算、范围检查和 3×3 支持筛选迁移为 C++；[depth_producer](视觉算法/软件/数值深度接口候选/native/depth_producer.h) 可将过滤结果接入原生编码和缓存发布。它接收已算出的视差和窗口掩码，并非完整 SGBM、校正或相机服务；监控统计未迁移。

主机差分测试 4 项通过：包括随机视差、无效数、量程与视差相邻边界、真实历史双目图片经现有 SGBM 算出的视差；有效掩码逐点一致，深度按绝对及相对容差 `1e-6` 核对。原生链路和 CMake Release 构建的 CTest 3/3 通过。历史图片与现有标定只能用于实现对照，不构成独立距离精度验收。

[主机原始微基准](视觉算法/软件/数值深度接口候选/native/evidence/filter-host-20261113-215603.json)记录输入及源码 SHA、1000 次样本、工具版本及统计：同一历史图像的 240×131 视差，Python 过滤函数中位/P95/P99 为 815.95/1039.0/1134.3 µs，C++ 候选为 109.9/165.9/204.9 µs。Python 路径还计算统计信息，C++ 输出预分配且不计算这些统计，故这不是完整等价工作量；也未记录温度、频率和功耗，不能用于宣称目标板或整条视觉链的加速倍率。板端数据分布、准确性、性能和热稳态仍待验证。

过滤器增加由调用方提供的可复用工作区，原有分配式接口保留；固定规格的 `StereoSgbm` 在构造时分配并跨帧复用该区，过滤阶段不再每帧申请临时区。工作区必须独占且不与输入输出重叠；其他 OpenCV 图像和发布路径仍可能分配。五项差分/边界测试通过，覆盖重复使用、残留数据清除、尺寸溢出及容量不足时输出不变。最新 [主机滤波对照](视觉算法/软件/数值深度接口候选/native/evidence/filter-workspace-host-20261113.json) 的 1000 次中位数：分配式 110.2 µs，复用式 110.1 µs，**未证明速度提升**；其作用是减少每帧动态分配，确定性收益仍须目标板测量。重新运行的 [主机整段对照](视觉算法/软件/数值深度接口候选/native/evidence/stereo-host-workspace-20261113.json) 中原生中位数 2.066 ms，仅是一次独立主机测量，不能与旧记录直接推断车端提升。

## 原生校正与 SGBM 候选

[stereo_sgbm](视觉算法/软件/数值深度接口候选/native/stereo_sgbm.h) 实现固定 0.375 比例的灰度缩放、标定映射、转正裁剪、SGBM 和原生深度过滤；支持现有 640×360 流和 3840×2160 传感器图像。构建须显式指定 `AGTC_WITH_OPENCV=ON` 和 OpenCV 开发包。离线 [export_calibration.py](视觉算法/软件/数值深度接口候选/native/export_calibration.py) 将已通过几何状态的 NPZ 转为 OpenCV YAML，保留原始 NPZ SHA，检查矩阵、单位、分辨率和基线方向，拒绝覆盖已有文件；这不证明标定精度，YAML 内的源 SHA 也不是 YAML 防篡改签名。

2026-11-13 在 Windows 主机以临时 OpenCV 5.0.0 开发包构建：对两组历史图像，包含 640×360 输入和其中一组 3840×2160 输入，共 3 个对照；当 Python 参考也使用 OpenCV 5.0.0 时，缩放、映射、校正图、视差及有效掩码一致，深度以 `1e-6` 容差通过，3/3。离线转换有效、无效状态及拒绝覆盖测试通过。源与输入哈希、图像差异计数见 [对照记录](视觉算法/软件/数值深度接口候选/native/evidence/stereo-replay-20261113/)。

**版本差异是明确的放行阻碍。** 同一 C++ OpenCV 5.0.0 与本机原 Python OpenCV 4.13.0 比较时，3 个对照均未通过逐像素等价；首组 640×360 例中，左校正图有 3,110/31,440 像素不同，视差 9,238 个不同，有效掩码 647 个不同。该例缩放和左校正映射一致，差异从重映射输出开始；目前不能仅凭版本号断言更深层根因。须确认实际板端 OpenCV 版本、使用同构建条件重新对照，并通过距离精度及系统验收后才能考虑替代；未实测该候选的目标板性能。原生采集、完整 HTTP 服务、标定和监控仍未迁移，禁止把此候选作为已完成部署。

[同版本主机整段微基准](视觉算法/软件/数值深度接口候选/native/evidence/stereo-host-20261113.json) 对一组历史图像的 640×360 输入，分别在 Python/OpenCV 5.0.0 与 C++/OpenCV 5.0.0 执行缩放、校正、SGBM 和过滤；各预热 5 次、采样 100 次，限制 2 线程。Python 中位/P95/P99 为 3.3672/3.7034/3.9481 ms，C++ 为 2.07575/2.2859/2.43 ms，输出的视差和掩码一致、深度在容差内。两者分别使用 Python wheel 与 MSYS2 编译包，虽然版本号相同，构建配置不完全相同；Python 过滤还计算统计信息，C++ 没有。测量在两个进程顺序执行，未监测热、频率和功耗，且不包括采集、页面、HTTP 或目标板，不能作为整车加速率或验收结果。

## 从双目图像到深度帧的原生连接候选

[stereo_publisher](视觉算法/软件/数值深度接口候选/native/stereo_publisher.h) 串接图像、SGBM、深度编码和缓存：校验两幅灰度图、共域 PTS 偏差以及到达时间，在计算前后检查帧年龄；原子发布序号、管线代次、载荷和元数据。阈值沿用现有软件的 25 ms 配对、处理前 0.75 s 和处理后 1.5 s，并非实车安全限值。它拒绝重复左 PTS 的再次发布、拒绝时间回退；无效、过旧、时间差过大或计算失败会在代次仍匹配时清除旧缓存，旧代次不得清除新代次的数据。与原服务相比，部分失效行为更保守，集成时须核对上层接口。

同版本主机回放 4 项通过：三组输入从历史图像运行至发布载荷，与现有 Python wire 编码逐字节对照，并核对序号、PTS、标定 ID 和由投影矩阵派生的 K；生成的 HTTP 响应经现有深度探针检查通过，另覆盖坏标定与输入尺寸拒绝。测试夹具注入过旧、未来时间、左右时间差、重复与回退 PTS、计算后过期、恢复递增序号及计算中管线切换；C++ 缓存测试覆盖旧代次不得清理新缓存。实际相机采集、PTS 域、双目曝光同步、数据到达时钟映射、异常断连与整车时限均未验证。调用方必须保证两个输入帧确实属于传入代次、图像在处理期间不被修改，且该发布器独占其缓存；预处理 ID、车体外参和来源时钟映射保持空值，不能据此声明可用于实车定位或运动。

## 双目采集与配对候选

[stereo_pair_queue](视觉算法/软件/数值深度接口候选/native/stereo_pair_queue.h) 保存每路最多 6 帧的独立副本，按到达时间新鲜度和运行时间 PTS 选择最近的左右帧；启动、停止和标定代次变化隔离旧帧。输入帧的像素在复制期间仍由调用方保证不被改写。[gst_stereo_capture](视觉算法/软件/数值深度接口候选/native/gst_stereo_capture.h) 可构造两路 V4L2 NV12 管线，并从命名 appsink 提取灰度面、真实步长与 segment running-time PTS。相机停止、单路 EOS、无效帧、时间回退或 GStreamer 总线错误使当前采集代次失效；调用方须持续轮询、在对象销毁前停止并等待采集线程，负责重启和错误报告。组件不实现曝光同步，也不把到达时刻当成曝光时刻。

主机使用临时 OpenCV 5.0.0 与 GStreamer 1.28.6 开发包构建，`CTest` 5/5 通过。appsrc 合成 NV12 测试覆盖 672 字节行步长与缓冲释放后副本、左右 PTS、旧代次、单路 EOS、总线错误、时间回退、阻塞采集期间停止及重启。`test_gst_end_to_end.py` 以合成 appsrc 帧运行采集、配对、SGBM、发布和 HTTP 响应，再用既有深度探针检查，1 项通过；该测试没有真实纹理或真实网络摄像机输入。现有测试未运行 V4L2 设备节点、真实摄像头断连或 RK3588 BSP；组件尚未接入生产服务，采集链的性能、功耗、重连、准确性和实车安全限值都仍待验证。

## 本机可运行服务候选

[vision_candidate_main](视觉算法/软件/数值深度接口候选/native/vision_candidate_main.cpp) 和 [vision_runtime](视觉算法/软件/数值深度接口候选/native/vision_runtime.h) 将双路采集线程、配对、SGBM 和深度发布连接至本机回环 HTTP `/depth.bin`，并可选提供固定色标 `/depth.jpg?scale=fixed` 和 `/stereo.jpg`。服务按有效深度请求激活计算，并在最后一次请求后保留 5 秒计算窗口；空闲时采集仍在运行。候选绑定 `127.0.0.1`，不提供原页面、自动色标、标定、监控、自动重连或服务管理，不能替代已部署服务。会话和单调时钟域标识由调用方提供，须与实际时钟一致；相机来源时间和车体外参仍未建立。

构建须启用 `AGTC_WITH_OPENCV`、`AGTC_WITH_GSTREAMER` 和 `AGTC_WITH_HTTP_SERVER`。HTTP 依赖外部 [cpp-httplib v0.18.3](https://github.com/yhirose/cpp-httplib/tree/v0.18.3) 单头文件，通过 `AGTC_HTTPLIB_INCLUDE_DIR` 指定；CMake 固定校验头文件 SHA-256 `a0a0c13dc086663863dbe6730a19716f7d3744904b6205496e8301750814dbd5`。当前主机测试依赖放在临时目录，不是已交付的目标板依赖。服务线程池限制为 4 个工作线程、16 个排队请求，读写超时 2 秒；Windows 使用独占端口选项，POSIX 路径仍待目标平台验证。Range 请求返回 400，不声称与旧服务所有 HTTP 行为完全一致。

主机 Release 全量重建后 `CTest` 6/6 通过，覆盖端口占用拒绝、等待请求期间关闭和原有缓存/采集测试。`test_vision_service.py` 以 GStreamer 合成 appsrc 驱动真实回环 HTTP，8 个并发客户端合计请求 16 次，既有探针核验成功响应；另验证无效请求不唤醒计算、空闲 5 秒后序号停止增长、采集停顿后旧缓存返回 503、总线故障后返回 503 和进程关闭。此为一次主机功能测试，不是负载极限、长期稳定、板端性能或实车验收；未接真实摄像头、生产网络或完整页面。Windows 端口独占问题经测试发现并修正，Linux/RK3588 的端口行为、时钟、设备、功耗与故障恢复仍待验证。

## 固定色标深度预览候选

[depth_preview](视觉算法/软件/数值深度接口候选/native/depth_preview.h) 仅在请求时根据已发布的 16 位毫米深度生成固定 0.3–5 m Turbo 色标 JPEG，按同一不可变帧复用编码结果；编码前后复查最新帧，避免将过期或切换后的缓存作为当前预览。响应携带来源深度帧元数据和序号。无效深度显示黑色，非法毫米值拒绝；源于毫米量化数据，与原服务使用未量化深度和自动色标的图像并不逐像素等价。为避免把固定色标误作旧默认自动色标，必须显式请求 `?scale=fixed`，无此参数或请求 `auto` 返回 400。

该功能需启用 `AGTC_WITH_PREVIEW` 并提供 libjpeg-turbo 开发文件；主机验证使用临时 libjpeg-turbo 3.2.0。Release 全量构建及 CTest 7/7 通过，覆盖 JPEG 解码、黑色无效值、近距离色标、同帧缓存、非法值和失效；合成采集的真实回环 HTTP 测试验证 JPEG 尺寸、类型、序号和故障后的 503。 [主机微基准原始记录](视觉算法/软件/数值深度接口候选/native/evidence/preview-host-20261113.json) 的 500 次合成深度样本中，Python 固定色标加 JPEG 编码中位数为 436.0 µs，C++ 新帧中位数为 366.7 µs，同帧缓存读取中位数为 0.3 µs。两者分别使用不同 OpenCV 构建及可能不同的 JPEG 库，缓存样本不执行编码，且未监测温度、频率或功耗；这些仅是主机微基准，不能作为车端或完整服务性能结论。

## 双目画面预览候选

[stereo_preview](视觉算法/软件/数值深度接口候选/native/stereo_preview.h) 按请求将左右灰度图并排编码为 1280×360 JPEG，640×360 输入不缩放，3840×2160 输入使用线性缩放；质量参数 55。相同源帧复用 JPEG，预览请求不启动深度计算。显示配对与旧服务一样不强制 25 ms 深度配对限值，但仍要求两路帧新鲜；响应标明两路 PTS、差值和曝光同步未验证。采集错误、停止或帧过期时返回 503。它是显示接口，不可把画面配对视为已同步的测距数据。

主机 Release 全量构建及 CTest 8/8 通过；测试覆盖灰度 JPEG 解码、左右位置、4K 缩放、缓存复用、编码中失效和非同步显示配对。合成 appsrc 的真实回环 HTTP 测试确认预览画面、时间戳头、预览不唤醒 SGBM，以及采集停顿或故障后返回 503。真实 V4L2、曝光同步、显示链长期稳定及板端资源仍待验证。

250 次合成均匀画面的主机微基准中，复用 JPEG 工作缓冲前的 [原始记录](视觉算法/软件/数值深度接口候选/native/evidence/stereo-preview-host-profile-20261113.json) 中位数为 564.5 µs；复用后的 [原始记录](视觉算法/软件/数值深度接口候选/native/evidence/stereo-preview-host-scratch-20261113.json) 为 279.15 µs，同次 Python 基线为 371.9 µs，缓存命中为 0.3 µs。两次独立运行，Python 与 C++ 使用不同 OpenCV/JPEG 构建；不包含采集、图像复制、网络、温度和功耗，均匀画面也不代表实际场景。这些数值只用于本机定位分配开销，不是 RK3588 或整车收益。

## FOC 角度归一化异常输入

部署范围为 STM32G431 的 C 固件；[FOC 角度归一化](../固件/foc_driver/BusinessLayer/Src/bl_foc.c) 原先对无穷大和部分极大有限数反复加减一个周期，浮点值可能不发生变化而不返回；`bl_foc_set_angle_offset` 和 `bl_foc_set_angle_fixed` 可接收外部浮点输入，仓库搜索未发现其调用方，实际触发路径尚未确认。目标代码将常规输入保留在单次加减的快速路径，其余有限输入使用 `fmodf`；非有限输入映射为零，延续原有 NaN 约定，并新增编译检查禁止 fast-math/finite-only 模式破坏非有限值检查。无穷大原本卡住，修改后归零可能影响固定角设定或偏置，**不是停驱机制**；异常输入应如何拒绝、报警及安全处置仍须结合上层状态机确定，未经系统验证不得上车。极小负数舍入到一个周期时现规范为零；较大角度使用取余可能与原多次减法的舍入结果不同。

基线为修改前该文件 SHA-256 `c054357fb07dc267e9eeb015aaf45aadfa0847a7a1ac864d3d7e52b682296ffb`，修改后为 `37fd287ac27552e31e9b026cc1e242166ce9bc61534c2509268ae068214646f8`。Windows x86-64、MSYS2 GCC 16.2.0、`-O2`，使用 [测试夹具](../固件/foc_driver/tests/test_angle_wrap.c) 和仅供测试的 `type.h` 替身：修改前 `inf` 与 `3.4028235e38` 均在独立进程的 0.5 秒超时内未返回；修改后 [回归脚本](../固件/foc_driver/tests/test_angle_wrap.py) 的 13 个边界/非有限输入及 100 个常用范围随机输入通过，其中 100 个逐值与修改前可执行文件比较相等。该结果不覆盖全部输入，也不构成实时最坏时间证明。`-ffast-math` 编译被预期拒绝。

以 ARM GCC 16.1.0、`-Os -mcpu=cortex-m4 -mthumb -mfpu=fpv4-sp-d16 -mfloat-abi=hard` 和相同测试类型替身编译生产源文件，单文件无错误或警告；**不是完整固件链接**，仓库未包含所需目标 `type.h` 和厂商 HAL/CMSIS。`fmodf` 的实际目标库依赖、闪存和栈占用、耗时及控制周期影响尚未确认。目标控制周期、截止时间、尾延迟、最坏时间、温度、频率、峰值及长时间运行预算均待定；需获取完整目标构建和设备，验证各输入范围、故障及恢复链，测量正常与异常路径并证明或界定实时上界。不得以主机超时或交叉编译代替板端性能、故障安全与验收。

## SLE 距离滤波重复排序

候选部署范围为 BS21E 测距 server；该自研滤波器为 C，依赖厂商 SDK 的 `common_def.h`，测距算法另依赖厂商预编译库，实际随车部署及设备配置尚待核对。[range_link_filter.c](../通信/src/sle_range_link/range_link_filter.c) 在窗口至少有三个样本时，其上次接受样本的输出就是当前窗口的中值；拒绝样本不会改变窗口或该输出。修改后复用此中值进行野值判定，避免在每个样本前再次排序。小窗口仍照原逻辑求中值，接受后的输出仍重新计算，重置与连续异常门控不变。Kconfig 当前默认窗口 16；此前 README 写为 1 已更正，实际固件生成配置仍未核验，窗口为 1 仍有野值门控而非完全直通。

修改前源文件 SHA-256 `600153998d74013308873594b5da6e1405c7432abd3c328dfb10d0cb9e49fd09`，修改后 `c94f7fe0fb6a69b571e6580cc63305a7ab11a37fd00b81d3d7ae787bb64285c5`。Windows 主机 GCC 16.2.0 `-O2` 使用仅提供 `NULL` 的 SDK 头文件替身，[差分测试](../通信/src/sle_range_link/tests/test_filter_differential.py)在窗口 1、2、3、8、16、32 下各比较 50,030 个输入，包含 0–50,000 mm 的稳定值、跳变、连续拒绝及跟随、重置、空计数指针；输出与有效计数均一致。测试不覆盖所有整数或真实射频测距链。原实现的 `int32_t` 差值、绝对值、相对门限乘法和窗口求和在极大输入下可能溢出；上游有效量程及其异常处理尚未证明，不能以本次差分结果覆盖该问题。

[主机基准原始结果](../通信/src/sle_range_link/tests/evidence/filter-host-20261113.json) 和 [基准脚本](../通信/src/sle_range_link/tests/benchmark_filter.py)：每版本 3 次、每次预热 5 批并测量 50 批，每批 100,000 个约 10 m、±200 mm 的稳定输入，交替运行顺序，使用 C `clock()`。窗口 16 的批次中位数由 13 ms 降至 8 ms，窗口 32 由 28 ms 降至 19 ms；窗口 1 的批次结果低于此计时器分辨率，无法判断差异。样本仅覆盖接受路径，批次时间不能作为单次尾延迟或最坏时间；未监控竞争、温度、频率和功耗，结果不是目标板加速率。

BS21E 的控制周期、负载、时间限值及内存/功耗预算待定；需用实际 SDK 和配置完整构建，核实数值范围并测试异常及恢复，在相同硬件上测量正常、峰值和长时间工况以及最坏时间。目标设备数据缺失，当前不构成车端验收。

### 滤波器整数边界修正

上面记录的整数溢出问题已在滤波器自身修正：差值使用有序无符号运算以覆盖 `int32_t` 两端的完整距离，中值绝对值处理 `INT32_MIN`，相对门限先分解再乘法，两个样本求均值时先扩展至 64 位。默认接口仍不拒绝负值，实际距离的物理有效范围与异常策略仍由上游及系统规范确定。此前测得重复排序优化的版本作为本次基线保存在[测试证据](../通信/src/sle_range_link/tests/evidence/filter-before-arithmetic.c)中，SHA-256 为 `c94f7fe0fb6a69b571e6580cc63305a7ab11a37fd00b81d3d7ae787bb64285c5`；本次修改后源文件 SHA-256 为 `2c47e7e3ee21b79cb96471e698cf06e995ebe67a95cb1684f7a999853b3279a5`。

修改前在主机窗口 1 的测试中，先输入 `INT32_MAX` 再输入 `INT32_MIN`，第二次错误接受了应拒绝的跳变；旧代码发生有符号溢出，不能将该结果推广为其他编译器必然行为。修改后，[独立整数参考测试](../通信/src/sle_range_link/tests/test_filter_extremes.py)在窗口 1、2、3、8、16、32 各验证 30,184 个样本，包含整数两端、相对门限附近、随机值和连续异常重置，输出及计数均一致；另以此前版本为基线完成每窗口 50,030 个常用范围样本的差分测试。GCC 16.2.0、`-O2 -Wall -Wextra -Werror`；这些是主机合成输入，非穷举或完整链路验证。

与本次基线同样方式进行的[主机批次基准](../通信/src/sle_range_link/tests/evidence/filter-arithmetic-host-20261113.json)，窗口 16 的中位数均为 8 ms、窗口 32 均为 19 ms；窗口 1 低于计时器分辨率，不能判断差异。它只覆盖稳定接受路径，尚无目标架构构建、周期、栈或实际功耗数据。上游 `rl_ext.c` 中浮点转整数、标定运算和拟合运算的输入范围及溢出防护尚未完整证明，本次未改变上游处理，不能宣称整个测距链已消除数值风险。
