# 农田探索最小环境 v0.1

纯 NumPy 几何 + Gymnasium 连续控制环境。默认策略深度观测为2×160×88；小车视角以伪彩色显示策略收到的同一帧深度值与有效掩码。可选WebGL植株几何视图仅用于调试，默认不初始化WebGL。无需Gazebo、WSL、真实图像渲染或真实视觉网络。搜索与到点共享同一观测、四维动作和可学习LSTM记忆；当前自身状态为44维。

本阶段曾加入平滑地形和石块代理，并以旧的±0.03m地形幅度完成44维状态短训练自检、地形基准和62项测试；这些记录只对应旧参数。当前默认地形已改为幅度±0.35m、波长4–10m；此前±0.25m的地形验证记录也只对应旧设置。旧模型的四个评估回合均以time_limit结束，尚未通过任务能力验收。**未实现对抗生成者、学习式报告／结束头、实车部署。**

## 打开界面

在上一级目录双击 `启动农田仿真.cmd`，打开 <http://127.0.0.1:8765>。仅监听本机。

也可以在上一级目录运行：

```powershell
.\.venv-field\Scripts\python.exe -m field_sim serve
```

训练地形版模型后，载入88×160深度输入模型：

```powershell
.\.venv-field\Scripts\python.exe -m field_sim serve --checkpoint results/field_mvp/training_terrain/checkpoint.zip
```

界面选“策略”才会使用模型；默认是**规则演示，不是训练成功的AI**。选“手动”后，W/S前后、A/D转向、Q/E云台偏航、R/F俯仰。手动油门默认25%，可调至100%；这与“仿真倍速”独立。点击地图设置目标并切换到点模式；点击车体不可达位置会显示错误。切换任务／目标不重置场景，重置按钮才新建场景并清空策略隐藏状态。当前地形版checkpoint使用44维状态；旧42维状态checkpoint不兼容，新模型也尚未通过任务能力验收。

上方可切换**俯视地图／小车视角／双视图**。小车视角显示策略所用的同一帧160×88深度输入：有效点按Z深度着色，近处偏暖、远处偏冷，无效点为黑色；伪彩色不表示叶片健康／干枯状态。深度帧按仿真时钟以2.5Hz采样并延迟300ms送达，UI状态按10Hz轮询，策略决策按20Hz运行；帧间显示最新已送达图像，不会把重复帧当新传感器证据。2.5Hz是仿真代理配置，参考实机约2.3Hz，不保证实机时序。可显式切换到WebGL几何检查视图，仅供调试；默认不初始化WebGL。场景默认含平滑起伏地面和随机石块，植株仍为散点布局，没有实现田垄、沟渠或作物行通道。俯视地图按真实世界比例绘制物体，不设最小屏幕尺寸：车体按0.8×0.3m矩形显示，石块按实际半径绘为圆盘，植株显示真实叶片几何的俯视轮廓，不用根部半径代替冠层。棕色地面使用`#766547`为基色，另按同一组正弦地形的高度和解析坡度显示明暗（高处较亮、低处较暗）；关闭地形或平地时仍显示纯棕色。新接口还可用侧栏地形控件设置高度幅度（0–1m）和最短波长（2–16m，最长波长为其2.5倍，短波长让起伏更密），点击“应用并重建场景”后以当前随机种子和任务模式重新生成。只在场景配置包含波长参数的服务上显示该控件。植株、石块颜色分别为健康`#4a8639`、干枯`#b17b42`和石块`#899195`，场地外为深色。车头朝向线在世界yaw=0时向右、yaw=+π/2时向上；另有青色炮塔／云台朝向线，计入云台方向。朝向线和状态、目标等辅助标记使用固定屏幕像素，不表示物体的物理尺寸。默认以车辆为中心显示4×局部视野并跟随车辆。俯视地图叠加两路传感器数据：LiDAR有效回波按采集帧方向与实测距离绘为端点（8m、400束、10Hz）；青色虚线为同帧全部有限扫描方向按标称最大量程8m生成的扫描平面XY轮廓，水平时为圆，云台俯仰后投影为椭圆，只表示量程边界，不表示实测可见范围或回波；深度相机将88×160有效像素的相机轴向Z深度（5m上限）经内参矩阵K和采集姿态回投，显示命中的地面及物体表面点（2.5Hz）。淡色虚线框是针孔深度视锥上限的俯视XY投影，只表示几何边界，不表示无遮挡可见面；仅显示有效首命中点，不以凸包连线或填充遮挡空洞。叠加按传感器帧序号缓存，并按屏幕像素去重，随地图缩放和车辆跟随更新。雷达和深度各自带有采集姿态与延迟；深度帧可能比当前状态旧300ms，因此回投点与当前云台朝向线不完全同步是预期行为。地形、植株和石块底图为仿真真值调试显示；叠加的可见点来自与策略相同的传感器已送达帧（包含量测噪声），策略不接收底图真值，只能通过传感器数据感知地面和障碍物。

俯视地图可用鼠标滚轮或“−／+”按钮在1–12×间缩放，1×显示全图，默认4×并开启跟随。跟随时车辆保持居中；暂停跟随后，滚轮缩放以光标位置为锚点。左键拖动地图超过5px会取消本次点击设定目标，并暂停跟随；“跟随”恢复车辆居中，“全图”恢复1×全图并重新开启跟随。调整窗口大小会保留当前缩放和中心位置。“量程”会按传感器叠加范围自动调整缩放并恢复跟随，便于查看有效回波点和深度视锥投影框；辅助线可跨越地块边界，仍按真实米制比例绘制。本次浏览器交互验收确认：默认4×跟随，放大按钮从4×增至5×，拖动会暂停跟随且不会设定目标，滚轮可缩放至12×，点击“跟随”恢复居中，“全图”恢复1×。

可选的WebGL几何调试视图使用本地vendored Three.js 0.183.2，无运行时CDN依赖；仅进入该视图时才初始化WebGL，默认深度视图与俯视图不依赖WebGL。Three.js采用MIT许可证，版本来源和校验值在 `web/vendor/THREE_VERSION.json`。浏览器不支持WebGL2时，几何调试视图不可用，深度视图、俯视图和控制仍可用。

`/api/scene` 的 `leaf_geometry`、`terrain`和`/api/state` 的 `view_pose` 专供调试绘制，不作为真值地图输入策略。`terrain`包含`wave_vectors4x2`、`wave_amplitudes4`、`wave_phases4`、`base_height`和`rocks`；石块含`x/y/z/base_z/radius/height/blocking`，植株也提供地形根部高度`base_z`。深度预览与策略共享送达帧及有效掩码；预览仅将该帧映射为伪彩色。

此前已对WebGL几何调试视图做过本机浏览器冒烟验证；该结果只说明可选调试渲染链路工作，不代表当前默认深度显示或地图已具备足够训练难度。

## 已确认参数与假设

| 项目 | 本版配置 |
|---|---|
| 场地／布局单元 | 100×100m／0.5m；400株随机植物，可通过CLI调整 |
| 作物／株高 | 玉米几何代理，默认约1m，各株在0.95–1.05m之间 |
| 车体 | 0.8×0.3m，差速运动代理，允许原地转向 |
| 最高车速 | 15km/h = 4.1667m/s，允许倒车 |
| 相机中心／俯仰限位 | 离地0.4m；−25°～+60°，正值仰角 |
| 角速度与加速度 | **未实测假设**：车体1.5rad/s、1.5m/s²；云台偏航1.8rad/s、俯仰1.2rad/s |
| 决策步长 | 默认0.05s，即20Hz；`--hz`可改 |
| 雷达型号／扫描 | X2，360°，8m，每圈400束，最小量程0.12m（按用户截图） |
| 感知更新／延迟 | 雷达10Hz／30ms；深度代理2.5Hz／300ms（参考实机约2.3Hz，不保证硬件时序）；检测5Hz／120ms（检测为代理参数）。策略20Hz、UI状态轮询10Hz，均独立于传感器采样／延迟 |
| 地面／石块 | 默认4个随机相位正弦分量生成平滑地面，幅度预算±0.35m、峰谷高差理论上限0.7m、波长4–10m；各seed的实际高差随随机相位变化，不保证达到上限。石块密度0.01颗/m²，100×100m约100颗，约20%为大石，实际数量随seed变化 |
| 定位 | UWB位置代理噪声2.5cm；未实现完整惯导融合、滑移或磁干扰 |

每株默认8片长窄、尖端收窄的双面叶片，在茎的不同高度交替向两侧伸出，同株干叶／健康叶可互相遮挡。株高默认1.0±0.05m；细茎半径默认约0.012m并小幅变化，属于待实测校准的近似参数。压损／导航仍使用单独的0.09–0.15m根部范围，避免把细茎和压损区混为一谈。叶片目前是平面近似，尚未模拟玉米叶拱垂、叶鞘或风动。形态参考玉米的直立茎、交替长带状叶特征（[Purdue Plant ID](https://www.hort.purdue.edu/plant-id-pal/Vegetables/corn.html)）；精确尺寸以用户实测为准。

默认地形由4个随机相位的正弦波分量叠加，幅度总预算为±0.35m，波长4–10m，理论峰谷高差不超过0.7m；每个seed的实际范围由随机相位和波向决定，不保证达到理论上限。这是平滑起伏面，不是每个位置独立加噪声。默认石块密度为0.01颗/m²，100×100m场景约100颗，约20%为大石，实际数量由随机场景决定。小石半径0.04–0.10m、高0.03–0.08m，可越过，并按准静态支撑计算车身高度、roll和pitch；大石半径0.15–0.30m、高0.15–0.30m，作为硬阻挡，运动段sweep用于避免穿透。地面与石块会影响深度／LiDAR回波并遮挡目标检测；石块和地面真值不直接暴露给策略。石块尺寸仍是待校准的实机代理。

可用 `--terrain-amplitude 0.35 --terrain-wavelength-min 4 --terrain-wavelength-max 10` 调整地形幅度和波长范围，`--rock-density 0.01` 调整石块密度；`--flat-ground` 同时关闭地形起伏和石块，便于平地对照。侧栏调节器的波长范围固定为`min`至`2.5×min`；场景地形和石块布局由seed复现。

默认深度栅格为H160×W88，策略观测形状为2×160×88。真实LightStereo输出为H640×W352的float32相机轴向Z深度，单位米，无效像素为NaN。内参来自[LightStereo几何快照](../../视觉算法/软件/LightStereo源码/models/portrait_geometry.npz)：原生矩阵中的fx=fy=393.29918355、cx=177.54501597、cy=323.73144277。缩放内参时遵循像素中心规则 `f'=s f`、`c'=(c+0.5)s-0.5`；缩至88×160后，fx=fy=98.32479589、cx=44.01125399、cy=80.55786069。深度射线采用这组矩形针孔几何，按相机Z值表达，不使用旧的正方形60°视锥径向距离。

策略深度通道为归一化Z值和有效标记。模拟无回波使用有限的最大深度值（5m）作为sentinel，归一化后为1，并将有效标记置0；实机适配时也要将NaN替换为同一有限sentinel并置有效标记0，避免把NaN送入策略。小车视角显示相同的160×88帧，近处偏暖、远处偏冷，无效点为黑色；这是深度伪彩色，不是RGB渲染，也不编码叶片状态。深度每0.4s采样一次、延迟0.3s；策略每0.05s更新、UI每0.1s轮询，重复帧仍可由新帧位和传感器年龄区分。

目标识别仍使用独立的60°圆锥视场代理；针孔内参仅用于深度栅格射线。检测只在7m内计算少量叶面可见性采样，模拟漏检／误分类与置信度，尚未按实车标注数据校准。雷达为随云台倾斜的360°单线扫描平面，400束、10Hz、8m最大量程和0.12m最小量程。三个传感器共中心近似，未模拟真实安装偏置和双目基线。

待接入的测距流程已确认设计：策略可将云台转向检测框，再触发同云台单点测距并关联检测结果；当前尚未实现，不改变当前观测字段或维度。

株高可通过 `--plant-height 1.0 --height-spread 0.05` 调整；两项分别是平均高度和绝对米制偏差，不是百分比。

X2当前默认配置为 `--lidar-rays 400 --lidar-hz 10 --lidar-range 8 --lidar-min-range 0.12`；深度默认配置为 `--depth-width 88 --depth-height 160`。在20Hz物理步进下，雷达每100ms采样一次，保持10Hz；深度每400ms采样一次、延迟300ms，是对约2.3Hz实机节奏的仿真代理而非硬件时序保证。跨越多个传感器周期时只采当前位姿一帧，遗漏周期计入 `info.sensor_dropped`。整圈仍按瞬时采样处理，暂未模拟圈内运动畸变。

当前雷达观测为2×400（归一化距离、有效标记）；深度观测为2×160×88（归一化Z、有效标记）。旧16×24深度checkpoint与当前观测空间不兼容；新增车身roll／pitch后，自身状态也由42维变为44维，因此旧88×160 checkpoint同样不兼容。`results/field_mvp/training_x2_400/` 和 `benchmark_x2_400.json` 是旧16×24配置记录；此前88×160无地形checkpoint与基准仅作历史对照。

识别相机视锥半角30°（全角60°）；深度图另按LightStereo针孔内参投影。雷达独立扫描完整360°，仿真及策略使用全部400束；俯视感知叠加显示有效LiDAR束的首命中端点和深度有效像素的针孔回投点，不以8m标称量程圆代表实际回波。俯仰时雷达扫描平面会倾斜，部分射线可能提前打到地面。原生双目深度仍使用LightStereo的88×160针孔Z深度栅格，最大深度为5m；该相机量程与雷达8m最大量程是不同传感器的设置。

雷达按实车约定与相机一起俯仰。正俯仰时前向半圈朝上、反向半圈朝下，负俯仰则交换；朝上射线可越过1m植株，向下则先碰地。初始云台改为水平。规则演示的到点任务保持水平，搜索按24s周期进行水平→上扫→水平→下扫，以免长期只看地面或天空；学习策略仍输出原四维动作。

雷达回波调试数据中的 `valid/hit_kind/scan_pitch` 用于说明各束回波状态，`hit_kind`不进入策略观测。无回波表示该射线在8m量程内未命中物体，不代表8m处有障碍；俯视地图仅绘制有效束的首命中回波端点，未命中束不显示为障碍物。

生成场景时验证车体外接圆的保守通道连通性，并检查每个干枯目标至少有一个采样观察位姿。验证不构成所有可能视点的穷尽证明。完整真值、验证栅格和目标ID仅供模拟器／裁判／调试UI使用。

压损根据整个运动段上插值的旋转车体轮廓与植株根茎范围判断，避免高速跨越漏算；每株只记一次，默认扣分继续。**暂不改变压损后的叶片几何，也不模拟倒伏动力学。**

## 环境接口

```python
from field_sim.env import Config, FieldEnv
env = FieldEnv(Config(), mode="search")
obs, info = env.reset(seed=7)
obs, reward, terminated, truncated, info = env.step([0.2, 0.0, 0.1, 0.0])
env.set_goal([20, 30])  # 同场景切换到点；策略使用者保留自己的隐藏状态
```

动作是 `float32[4]`、每维−1～1：`[速度指令/最高车速, 转向角速度/上限, 云台偏航角速度/上限, 云台俯仰角速度/上限]`。底盘速度受加速度限制，角度使用弧度。x向右、y向上、z向上；yaw逆时针为正；camera正俯仰为抬头。

观测Dict：

| 字段 | 形状 | 含义 |
|---|---|---|
| lidar | 2×400 | 归一化距离、有效标记 |
| depth | 2×160×88 | 归一化相机Z深度、有效标记；无效值为有限最大深度sentinel且有效标记为0 |
| detections | 16×10 | cx/cy/w/h、类别、置信度、距离、距离有效位、框有效位、预留位 |
| state | 44 | 任务类型、到点相对位置、带噪自身位置、方向、实际速度、云台角度、上一实际控制量、时间进度、dt、目标容差、各传感器年龄／新帧位／采集后相对运动、车身roll／pitch |

`state`索引：0–1任务one-hot；2–3车体坐标系目标差；4–5带噪位置；6–7航向sin/cos；8–9速度／转速；10–12云台yaw sin/cos和pitch；13–16上一实际控制；17时间进度；18 dt；19到点容差；20–26雷达年龄、新帧位、采集后dx/dy、车头／云台yaw／pitch变化；27–33深度同结构；34–40检测同结构；41定位噪声尺度；42–43车身roll／pitch（弧度除以π归一化）。

每路观测按模拟时间独立采样、延迟交付，保留采集姿态；reset的首帧即时初始化。旧帧重复读取不产生新报告。速度增加不会让传感器凭空增加新帧。`info`含裁判真值统计，仅用于奖励、日志和显示，不作为策略观测。

## 任务与奖励

- 搜索：新正确植株报告+1，唯一误报−0.25，压损每株−4，每秒−0.01；全部目标找到+5；超时按遗漏比例最多−2。
- 到点：进入0.4m容差且车速<0.2m/s、转速<0.3rad/s，持续0.3s后+5。另有0.15×距离改善的训练辅助奖励；时间与压损同上。
- 越界会限位并增加按时间累计的代价。

**MVP有意缩减**：高置信度干叶检测、且有距离时自动触发报告；重复检测同株不重复计奖。搜索终止由评估器发现全部目标，或超时决定，**网络尚未学会自主报告与判断完成**。没有向策略暴露真实目标数。标记精确世界坐标与跨相机外参融合将随实车适配器补充；目前使用模拟检测关联评价唯一植株。

## 依赖与下一阶段

## 随机起点与最新课程结果（2026-10-17）

`FieldEnv.reset(options={"random_start": True})` 可从当前场景的空地采样车辆起点；`NavigationCurriculum` 另按seed采样课程起点，20%沿用默认起点，其余在距边界8m的范围内均匀采样位置与朝向。两者均不改变策略观测。Gazebo 的 `MixedTaskWrapper` 也会在未给显式起点时传递 `random_start=True`，但现有检查仅验证真实 `FieldEnv` 与 mock wrapper 的采样／参数传递；Gazebo 物理随机出生尚未验收。

训练入口 `simulation.improve_field_policy` 支持 `--device cpu|cuda|auto`（默认CPU）、`--vec-backend dummy|subproc`（默认`DummyVecEnv`）和非负 `--distance-cost`（默认0）。距离代价仅包装训练环境奖励：`r' = r - distance_cost × 当前目标距离 × dt`；固定seed验证和评估不使用此变换。可用SB3现成向量环境，不另写训练框架。

最新一轮 `easy_distancecost_gain100_20261017_164842` 请求训练32768步，在240s墙钟上限内实际完成16384步；配置为4个 `DummyVecEnv`、CPU、`goal_gain=100`、`distance_cost=1`、seed 7，目标距离0.45–1.05m、±10°、`TimeLimit(160)`（8仿真秒）。同10个固定近目标任务由初始权重0/10到最新权重10/10，均无损伤／碰撞，平均49.3步结束；这只证明该简单分布上的到点行为。相同checkpoint在未改奖励的400株、默认地形、20s、3m固定seed验证仍0/3安全到点，平均目标距离约3.00m降至1.62m，无碰撞／损伤。结果分别见 `../results/field_policy_improvement/easy_distancecost_gain100_20261017_164842/near_goal_comparison.json` 与 `latest_complete_validation.json`；不代表田地避障、搜索或实车能力。对抗生成者仍未实现。

下一阶段继续做独立多seed全回合评估，再实现学习式报告／结束头，随后再考虑场景生成者。`reset(options={"scene": scene})` 已允许注入固定场景，`Scene.validate()` 是合法性入口；生成者不进入部署端。实车接入前还需确认运动参数、校准感知错误和延迟，并测试RK3588联合负载。
