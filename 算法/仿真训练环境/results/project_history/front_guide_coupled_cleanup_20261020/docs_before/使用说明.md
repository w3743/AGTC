# Isaac Lab 使用说明

## 联动前导向轮与崎岖地形检查（2026-10-20）

新增可选 `--front-guides`：左右各一只随同侧负重轮传动、无独立电机的前导向轮，半径45mm、宽60mm，轮心位于车体中心前方420mm、比原支撑轮轴高50mm。新增质量从车体扣除，总质量仍30kg；不增加驱动电机或扭矩额度；在原12条同侧负重轮关系上新增2条导向轮传动约束，每环境合计14条。当前半径相同，导向轮与同侧负重轮角速度为1∶1；通用关系按半径比保证带速一致。尺寸为试验假设，模型仍是离散轮代理，没有连续履带斜面或带面牵引力。原有14轮默认场景保持，旧模型和实验记录保留。

`--body-stability` 启用独立的车身稳定目标：惩罚超过35°试验软阈值的总倾角，以及车身X/Y轴角速度平方的时间积分；不要求车辆在正常坡面上保持水平。35°不是实车安全角标定，原1.2rad硬倾角终止保持。用于奖励与评估的是仿真车体真值，策略输入数量及连续四维动作不增加。

手动检查复用官方Viser，从实际USD资产显示新增轮，不加载旧checkpoint。示例使用独立端口，避免替换8769上仍运行的历史模型：

```bash
bash scripts/isaaclab_python.sh -m isaac_field viewer --mode goto \
  --plants 0 --rock-density 0 --front-guides --body-stability \
  --max-time 60 --seed 80003 --episode-seed 87001 \
  --reward-profile protect_plants --port 8781
```

不指定 `--goal-distance`，起点、朝向和目标按全场有效区域采样；不传 `--flat`，使用崎岖地形。检查页初始为手动、暂停状态；没有加载策略时不能把网络预览称为训练模型的实时激活。`--rock-density` 默认仍0.01，以上命令显式设0以先训练连续地形姿态控制。

新正式训练方案在既有fresh入口中，以 `random_rough` 独立保存：零植物、零岩石、100×100m、地形幅值预算0.35m、波长4–10m、60秒回合、4环境、新初始化196608步。每次运行导入一个固定地形，各回合随机起点、朝向和目标；这不等于每回合生成新地形。开发评估分别使用两份地形，0步基线和训练后模型必须匹配实际地形USD哈希、种子、配置及初态；缺失证据拒绝比较。旧的近距离课程保留为 `legacy_foundation`，新方案不续用旧几何的权重。

## 安装和运行环境

Windows 可使用根目录的 `安装IsaacLab.cmd` 和 `启动IsaacLab.cmd`。脚本复用固定的 `external/IsaacLab`，运行时位于共享 WSL 环境，不要把它当成项目清理目标。手动运行时使用 Ubuntu-24.04；默认 WSL 发行版可能是 docker-desktop。

  --checkpoint results/isaac_field_improvement/fresh_coupled_tracks_20261020/stage_04_turn90.zip

选中层后，右侧详情默认勾选“单图自适应色标”：只按当前所选完整激活或参数张量的有限值最大绝对值，确定独立的对称±范围，保留0同色，不截断大值。切换weight/bias会按对应张量重新计算；全零或无有限值用±1。预览下方显示自己的色条，主图仍使用顶栏全局色条。取消勾选即可让预览也使用全局统一范围。局部自动缩放有助于看清小幅变化，但不同张预览的相同颜色未必代表相同数值，比较前须看各自色条。API `detail_scale=local|global` 默认global，保留旧客户端兼容。

详细展开包含全部60个监控卡片，当前可学习模块层未发现遗漏；60不是神经层数，卡片还包括输入、融合、LSTM状态/重建门值、检测公式与独立价值诊断。reshape等函数级操作不各占卡片。

实际网络激活需要加载兼容的策略 checkpoint，并切到策略驾驶。随机初始化的正式 0 步 baseline 必须标明未训练。旧 PI-v6 策略与当前输入形状兼容，但其训练物理不同；重新评测时应同时保留 checkpoint 的训练 drive 与当前环境 drive，不改写旧 metadata。

## 模型输入和输出

| 分支 | 形状 | 说明 |
|---|---|---|
| LiDAR | 1×400 | 单路完整扫描，环形 Conv1d 编码 |
| 深度 | 1×160×88 | 单通道轴向 Z/量程；无效值为 0，无额外 mask 输入 |
| 检测 | 16×8 | 最多 16 个目标槽位 |
| 状态 | 33 | 目标、定位、任务状态、上一动作等当前契约字段 |
| 反馈 | 37 | IMU、磁场、四元数、云台实测角/速、等效左右电机 Iq/RPM及有效性/时龄 |
| 动作 | 4 | 左履带速度、右履带速度、云台偏航角速度、云台俯仰角速度 |

输入 schema 为 `sensor-minimal-v6`，编码器为 `depth64-lidar-single1d-minimal-v3`，五路特征融合为 192 维，再经过 128 维 LSTM。动作 schema 为 `direct-track-speed-v1`，四项均为归一化连续值 [-1,1]。本次修复物理模型，不改变这些输入、网络或动作维度。

ATK-IMU901 安装在随偏航和俯仰转动的云台上，不能把其读数直接称为车体 IMU。气压、海拔、温度和重复欧拉角不进入策略，磁场保留。仿真电流/RPM是由实际代理轮力矩/轮速换算的模型等效值，尚未完成实车标定或硬件联调，不能称为接触力传感器。

## 新初始化训练流程

1. 先通过车辆运动、接触、力矩限幅、多环境隔离、局部重置和 CPU 回归。确认源码后 prepare 新实验，保存协议、源码快照/哈希、依赖版本和资产哈希。
2. 从新的随机 RecurrentPPO 创建正式 0 步 baseline；不加载旧权重，不迁移旧 Adam。4 个环境分别交互采样，每环境收集 128 步，合计 512 条 transition。
3. PPO 按 batch 128、最多 5 epochs 更新网络；学习率 3e-4、gamma 0.995、GAE lambda 0.95、target KL 0.03。训练从高斯策略采样动作，评估和 viewer 使用确定性动作。LSTM 在回合内保存记忆，回合开始只清对应环境的记忆。
4. 按下表逐渐增加目标距离和转向角度。每 8192 条训练 transition 保存 checkpoint；总步数是所有环境 transition 的总数，不是单环境仿真子步数。
5. 训练自然退出后，在相同当前物理和相同初态下，配对评估正式 0 步 baseline 与 final。真实退出码、损伤、碰撞、到点成功和末距分别记录，训练完成不代表能力提高。

| 阶段 | 目标距离 | 初始目标角范围 | 新增训练步数 |
|---|---|---|---:|
| near | 0.6–1.2 m | ±15° | 32768 |
| steer30 | 1–2 m | ±30° | 32768 |
| steer60 | 1–3 m | ±60° | 65536 |
| turn90 | 1–3 m | ±90° | 65536 |

合计 196608 步，stage seeds 为 69001–69004。当前基础操控课程为平地、0 株、goto、20 s 回合；它没有训练植物识别、绕行或避苗。到点要求距离≤0.4 m、低速稳定 0.3 s，不要求终态朝向。损伤优先：允许慢或超时，不能以压苗换成功。

## 从已验证 final 继续训练

续训入口固定核验父实验 `fresh_coupled_tracks_20261020` 的协议、final checkpoint、CPU/Adam 验证和已知源码差异，再将 final 权重与 Adam 状态载入新的独立实验。环境、RNG、LSTM 状态和 rollout buffer 会重新初始化，因此这是带优化器状态的继续训练，不是逐位恢复原进程。输出目录默认是 `results/isaac_field_improvement/continue_coupled_tracks_20261020`，不可覆盖已有目录。

本轮采用 60 秒回合。运行 prepare 时显式指定 `--max-time 60`，然后先做 preflight；确认后才 launch：

```bash
bash scripts/isaaclab_python.sh scripts/continue_isaac_foundation.py --prepare \
  --output results/isaac_field_improvement/continue_coupled_tracks_20261020 --max-time 60
bash scripts/isaaclab_python.sh scripts/continue_isaac_foundation.py --preflight \
  --output results/isaac_field_improvement/continue_coupled_tracks_20261020
bash scripts/isaaclab_python.sh scripts/continue_isaac_foundation.py --launch \
  --output results/isaac_field_improvement/continue_coupled_tracks_20261020 --device cuda:0
```

60 秒会同时改变 episode 时间上限和策略输入 `episode_time_ratio`。续训实验会在这套 60 秒配置下重新评估父 final baseline 与新 final；不得把历史 20 秒成绩与这次结果混算。种子仍是开发集，先检查配对条件下无损成功和损伤门槛，再决定是否进行独立验证。

## 训练方法改进入口（独立实验）

`scripts/train_isaac_mastery.py` 复用现有 RecurrentPPO、原始奖励、Newton/Isaac Lab 环境和 `evaluate_model`。它提供固定步数对照与能力门槛课程两个独立实验，默认均新随机初始化、4环境、196608步上限、60秒回合、相同种子流和PPO参数。60秒终止与 `episode_time_ratio` 输入在两组中保持一致；这些实验不能与历史20秒成绩混算。新初始化的 `policy_tensor_sha256` 用于核验两组初始权重是否相同，ZIP文件哈希不代替张量比较。

课程先固定0.6–1.2m距离，依次扩大15°、30°、60°、90°目标采样角，再扩大到1–3m，最后以2、8、16株增加植物。每个阶段都会真实设置对应的 `Config.plants`；不再把零植株训练解释为已学会避苗。仍是goto课程，未加入搜索、石块或粗糙地形。并行准备的random_rough入口保持独立。

能力课程每完成8192个当前阶段实际训练步，用独立16-seed开发探针检查；无损、无碰撞到点比例至少80%、损伤及碰撞为0，连续两次达标才晋级。预算不足时保留未掌握状态，不会自动把未通过的阶段标为完成。阶段晋级后先重新采样最近的旧任务，随后按完整循环的当前/旧任务3:1目标分配进行分块训练；这是采集新的on-policy轨迹，未使用旧PPO rollout重放。有限预算中的实际比例以 `checkpoint_manifest.json` 的完成块为准。

最佳模型使用另外32个固定开发场景（8类任务各4个），每4次课程探针、每次晋级和训练结束时检查；同场景配置、seed、植物位置哈希、初始姿态和目标都必须配对一致。总无损成功数增加，且每类任务成功不下降、损伤回合/损伤总数/碰撞均不恶化，才更新最佳模型。`latest_checkpoint` 和 `best_checkpoint` 分别记录，最佳模型允许仍是正式0步baseline。开发探针用于调课程和选模，不能称盲测；83000–83999未使用，独立验证仍须在开发门槛通过后另行执行。

目录已存在时prepare会拒绝覆盖；启动器拒绝重复启动或覆盖日志、退出记录。正式训练应使用shell启动器：`python_outcome.json`只描述Python异常/正常返回路径，`python.exit_code`和`process_exit.json`由父shell记录实际退出。若进程被杀且无退出文件，仍须核实际进程，不能只看 `run_status.json` 推断完成。源码快照、协议、依赖、机器人规格、每次实际生成的USD资产哈希、各块检查点和Adam状态均保留。

`diagnostics.jsonl`逐rollout记录各动作维度、原始采样与传给VecEnv的裁剪动作、完整回合回报、奖励分项与PPO已有标量。奖励分项只观察原来的数值，不增加转向、刹停或势函数奖励；分项总和与实际回报的一致性也会检查。环境在同一步自动reset前保存终止步快照，避免官方快速SB3包装器丢弃自定义info。动作是策略命令，不能称实测履带速度。PPO的rollout-end回调发生在本轮优化前，指标对齐/缺失状态明确记录，训练结束额外记录最后优化结果。

后续参数对照可通过prepare的 `--gae-lambda 0.99` 或 `--gamma 0.997` 单独改变一项，其他条件固定；同一个对照中不能同时改变课程和折扣。现有训练阶段仍统一128步rollout，尚未解除历史入口的长度约束。不复用旧GAE脚本的2026-10-17权重或旧输入合同，也不根据0.89秒GAE衰减时长断言它是失败根因。

奖励方案先依据逐项日志检查“安全到点/合理绕行/正确刹停”是否优于绕圈或远离目标，再决定单独测试势函数塑形；直接奖励始终面向目标可能妨碍绕苗，不能直接并入本轮。纯延长时限对照仍需单独固定原模型的时间比例输入，本入口两组固定60秒不等同于已完成该对照。

仿真真值辅助critic作为后续架构对照：需要新的critic专用观测、策略分流和checkpoint schema；只设置 `share_features_extractor=False` 不会实现特权critic。部署actor应只接收实车传感器，并验证任意改变critic专用字段不改变actor动作；loader、viewer、激活采集也须同步新schema。当前入口仍保持原策略结构，不声称该架构已经实现或验证。

方案依据：[SB3 callbacks](https://stable-baselines3.readthedocs.io/en/master/guide/callbacks.html)、[RecurrentPPO](https://sb3-contrib.readthedocs.io/en/master/modules/ppo_recurrent.html)、[Isaac Lab课程机制](https://isaac-sim.github.io/IsaacLab/develop/source/api/lab/isaaclab.managers.html)、[非对称Actor–Critic论文](https://arxiv.org/abs/1710.06542)。当前采用自定义安全比较器，是因为默认按平均reward选择模型不能表达本项目的不压苗优先门槛；没有另写RL算法。

## 已知限制

- 仍是盒体、14 个圆柱滚轮和云台的轻量代理；同侧联动修复了机械关系缺项，但没有模拟完整柔性履带、土壤变形或真实单电机传动系统。
- 摩擦、P/I、每轮力矩、电流换算、噪声和外参均未实车标定；目前制动 probe 仍存在约 0.06 m 的反向速度积分，末段停稳不等于全过程没有回摆。
- 损伤采用 stem-contact-v2 的离散 2.5D 近似；叶片擦碰不算损伤，不能把它说成精确接触/折断模型。
- 实车 IMU/FOC 数据解码与 C 主机测试不等于串口/CAN/HAL 已完成实机联调；详细记录见归档说明和硬件协议文件。
- 完整作物搜索、粗糙地形导航、对抗训练和整田可靠性仍未完成。
