# 机器人虚拟实验室 1.0.0

新增独立的轻量农田环境：双击 **启动农田仿真.cmd**，浏览器打开 `http://127.0.0.1:8765`。支持搜索／到点、连续底盘与云台控制、植物压损、传感器延迟和短训练；无需启动WSL或Gazebo。配置、命令、实测性能及MVP限制见 [农田环境说明](field_sim/README.md)。

这是一个**联网部署包**。把整个压缩包发给别人，解压后安装，即可建立相同核心版本的实验环境。不包含已训练模型，不需要复制本机 WSL 系统。

## 第一次部署

建议使用 Windows 11 x64、16GB 以上内存、至少 30GB 实际磁盘空闲空间，以及支持 WSLg 的显卡驱动。本包的入门 PPO 使用 CPU；Gazebo/MuJoCo 图形优先使用可用的显卡。

1. 没有 WSL2 Ubuntu 24.04 时，以管理员身份打开 PowerShell，执行 `wsl --install -d Ubuntu-24.04`，按提示重启。第一次打开 Ubuntu，创建普通 Linux 用户和密码。已有其他 Ubuntu 版本时，请并存安装 24.04。
2. **完整解压**到本地磁盘可写目录，例如 `D:\robotics-lab`。不要在压缩包内直接双击。
3. 双击 **安装环境.cmd**，保持联网，等待出现“安装和基础检查完成”。首次需要下载依赖和编译 PX4。网络中断后可再次运行；版本或本地源码冲突时会停止并说明原因。
4. 双击 **启动实验室.cmd**，按编号选择实验。日后无需重复安装。双击 **检查环境.cmd** 可检查依赖、二进制和机械臂/手的步进渲染。

需要访问 Ubuntu 软件源、packages.ros.org、GitHub、PyPI、download.pytorch.org。安装日志在 `results/install.log`，检查结果在 `results/deployment.json`。失败时先看窗口末尾和这两个文件。

发行版名称不同时，在项目目录的 PowerShell 执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\windows.ps1 -Mode Install -Distribution 你的发行版名
```

安装成功后记住该名称。仍必须是 WSL2、Ubuntu 24.04、x86_64，默认 Linux 用户不能是 root。不会更改电脑的默认 WSL 发行版。

### LightStereo 低覆盖因素与改进记录（2026-10-04）

这里用**有效深度覆盖率和距离误差**衡量识别效果。覆盖率不表示像素距离正确；黑色表示没有有效输出。完整证据在 [acceptance.json](results/lightstereo/acceptance.json) 的 `study.low_coverage_factors`，原始 RGB、灰度、真值与前后预测在 `frames.npz`，图见 [comparison.png](results/lightstereo/comparison.png)。记录区分实测关联、对照支持、筛选规则和待验证假设。下表的“新视角”指菜单11的视角6～10；算法替换研究另用视角11～15。

| 因素 | 本次证据与判断 |
|---|---|
| 大面积低纹理平面 | 初轮7×7灰度方差≤4的区域占开发真值85.8%、验证真值92.8%；低纹理区覆盖19.3%，有纹理区73.1%。后续已完成同几何、同PBR渲染方式的纹理对照，确认其对本仿真的影响，见下方“表面纹理对照”。重复色块的影响仍未单独隔离。 |
| 亮度、对比度与模型输入分布 | 同一对图像使用相同 Gamma=0.45，保持模型、几何及 LR≤1px 不变，覆盖率和误差同时改善。该结果支持成像/预处理会影响表现，不能据此断言所有场景都需要提亮。 |
| 左右视差不一致 | 开发视角通过量程和双目视野支持后覆盖67.2%，LR筛选后剩17.4%。放宽到2px虽提高至25.2%，有效预测 MAE 却由0.418增至0.489m；亚像素采样没有明显改善。 |
| 量程与双目边界 | 当前只输出0.3～5m；新视角平均42.7%的图像真值处于量程外。这部分黑色属于量程限制。右眼对应位置越界也会被拒绝。预测深度越界单独记录。 |
| 远处视差小 | 约96.3mm基线、393.3px焦距下，5m处约7.57px视差；±1px可造成约0.58～0.76m距离误差。这是几何推算。 |
| 缩放补边与增强方式 | 576×960缩放补边、256行分块和独立CLAHE在同帧对照中均未同时改善覆盖和误差。原生352×640输入已避免大面积补边；该因素不能解释当前全部残留空洞。 |
| 灰度复制丢失颜色 | 本次原始RGB覆盖9.3%、MAE 0.589m，比灰度17.4%、0.418m更差；“缺颜色是主因”的假设未获支持。 |
| 深度边界与遮挡 | 按3×3真值深度跨度>0.25m分组。部分视角边界误差更大，例如第9视角边界0.65m、内部0.35m；遮挡机制尚未独立隔离。 |
| 训练域与实拍相机误差 | 使用现有SceneFlow预训练权重；Gazebo材质、照明、重复纹理的域差异未隔离。仿真同步、内参和墙面深度检查通过；实拍的标定残差、曝光、同步与模糊仍需独立测量。 |

菜单11先在视角1～5比较预处理；候选必须同时提高覆盖、降低MAE、P95和共同有效像素误差，再按误差≤0.1m的真值覆盖选择。参数选定后，在视角6～10保持不变验证。当前选中**灰度 + 同步 Gamma=0.45**，查表公式为 `round(255*(灰度/255)^0.45)`，两眼完全一致。

| 指标 | 原输入 | Gamma候选 |
|---|---:|---:|
| 开发视角：0.3～5m真值区域有效覆盖 | 17.4% | 37.5% |
| 开发视角：有效预测 MAE | 0.418m | 0.298m |
| 五个新视角：0.3～5m真值区域有效覆盖 | 23.3% | 26.9% |
| 五个新视角：有效预测 MAE | 0.346m | 0.305m |
| 五个新视角：共同134325像素 MAE | 0.234m | 0.187m |
| 五个新视角：误差≤0.1m的真值覆盖 | 7.6% | 8.9% |
| 五个新视角：整张输出的黑色比例 | 80.4% | 79.7% |
| 已有五对实拍：整张有效覆盖 | 47.6% | 48.6% |
| 实拍共同17867棋盘像素：平面一致性 MAE | 5.20mm | 4.88mm |

新视角4/5同时改善覆盖和MAE，第10视角覆盖下降；几乎完全无纹理的第7视角仍有1.19m MAE。新视角视差误差>3px的有效像素比例由11.7%升至15.6%，也说明改善并非所有误差指标都更好。实拍平面来自同一标定的PnP，仅检验一致性，不是独立距离真值；这些照片也已用于此前实验。当前结果支持把Gamma作为实验候选，尚未验证板端性能或实机避障精度。

菜单11可复现本次预处理研究，也可在WSL运行 `bash scripts/launch.sh lightstereo-study`。菜单10～12共用最近一次结果目录。算法替换研究及残留问题见下一节。

模型契约与机制参考官方 [SceneFlow配置](https://github.com/XiandaGuo/OpenStereo/blob/v2/cfgs/lightstereo/lightstereo_s_sceneflow.yaml) 与 [LightStereo论文](https://arxiv.org/abs/2406.19833)。

### 替换算法提升距离精度（2026-10-04）

已实际比较 SGBM、现有 LightStereo、RAFT-Stereo Middlebury/RVC、FoundationStereo small 的 RGB/灰度输入，以及两种左右一致性策略和 LightStereo 回退组合。权重未训练。用视角1～5选择并冻结方案，随后评估已有视角6～10和另行采集的视角11～15；仿真深度不参与预测或有效性筛选。

当前实验候选是 **RAFT-Stereo Middlebury + LightStereo Gamma 回退**。RAFT 采用原生352×640输入、32次迭代、FP32；在对应右眼坐标处，要求左右预测距离差≤`min(0.1m, 预测距离的5%)`。RAFT 通过筛选时优先使用，否则保留通过原有1px左右筛选的 LightStereo Gamma 输出。仍只接受0.3～5m和双目视野内的像素，不做空洞插补；`replacement_source` 记录每个像素的预测来源。

下表比较此前的 Gamma 方案和本次融合方案。覆盖率以量程内真值区域为分母，MAE为各自有效区域的汇总平均绝对误差。

| 视角组 | 有效覆盖：Gamma → 融合 | 距离 MAE：Gamma → 融合 |
|---|---:|---:|
| 开发1～5 | 37.5% → 47.1% | 0.298 → 0.240m |
| 已有验证6～10 | 26.9% → 29.9% | 0.305 → 0.237m |
| 新验证11～15 | 38.1% → 47.3% | 0.246 → 0.182m |

新验证中，**误差≤0.1m的真值覆盖率由13.6%升至28.6%**；共同有效344,520像素的MAE由0.246降至0.181m，整幅图黑色占比由67.8%降至60.4%。已有五对实拍棋盘的整图有效覆盖由48.6%升至64.5%；共同有效18,100棋盘像素的平面一致性MAE由4.91降至1.11mm，五对均改善。该平面由同一标定的PnP求得，这些照片也已用于此前实验，**不能视为独立真实距离精度验证**。

本次同时记录了未解决的问题：

- **固定像素阈值的距离含义不同。** 远处小视差使1px对应较大距离差，改用距离一致性筛选可以收紧这部分输出；左右一致仍不能证明预测正确。
- **更强模型也会产生错误近距离输出。** FoundationStereo 灰度方案的开发覆盖达到53.3%、有效区域MAE为0.122m，但有165,495个真值量程外像素被预测成量程内；同期Gamma为8,462个，因此未选中。FoundationStereo RGB及RAFT RVC也未通过联合选择条件。SGBM的距离误差较小，但覆盖明显不足。
- **低纹理视角仍差。** 新验证第12视角MAE由0.899升至1.111m；其他四个新视角MAE改善。新验证整体误差P95由0.831升至0.908m，不能声称所有误差指标改善。
- **量程外误判仍需控制。** 新验证由18,321增至19,790像素；已有验证由45,614增至67,920，后者超过开发时采用的新增0.5%整图像素限制。`replacement_study.limitations.validation_guardrails_passed=false`，当前只证明平均精度和覆盖改善，尚未达到实机部署验收条件。

影响实际精度的剩余缺口是独立距离真值的低纹理实拍、标定残差/同步/曝光诊断，以及量程外错误预测控制。后续已经完成保持几何不变的表面纹理对照，结果见下方。

**运行入口：** 本机先运行菜单11建立十个基础视角，再用菜单12追加五个固定验证姿态并完整重算。已有十五帧时，可直接用 `.local.json` 的 `stereo_python` 运行 `simulation/compare_stereo.py --cache <stereo_cache>`，复用数据且覆盖同一结果目录。再次运行菜单10/11会覆盖替换研究结果。

菜单12使用 Windows CUDA 环境；本机已配置 `stereo_python` 和 `stereo_cache`。源码、权重和虚拟环境集中在本地缓存，未放入交付包。运行版本是 Python3.11.9、Torch2.8.0+cu128、CUDA12.8、NumPy2.4.6、OpenCV4.13、ONNX Runtime1.28、timm1.0.30；虚拟环境复用现有GPU Torch。RTX5070Ti Laptop 上新验证融合平均约0.707秒/图像对（含左右推理及CPU LightStereo回退）；这是桌面实验性能，**尚未移植到RK3588 NPU**。

迁移到其他电脑时，需要另外配置上述 Windows GPU 环境和缓存，并在 `.local.json` 填入两个绝对路径，保留原 `distribution`。缓存须含官方 [RAFT-Stereo](https://github.com/princeton-vl/RAFT-Stereo) 提交 `6e93ed2169bd858dbb43033988563f3b0bb49506` 的 `models/raftstereo-middlebury.pth`、`models/iraftstereo_rvc.pth`，以及官方 [FoundationStereo](https://github.com/NVlabs/FoundationStereo) 提交 `6e8806816b533e4d13ddbb95ffa907b797060a62` 的 `pretrained_models/11-33-40/cfg.yaml` 和 `model_best_bp2.pth`。RAFT权重通过其 `download_models.sh` 获取；Foundation通过其README的预训练权重目录获取。RAFT代码为MIT；本次Foundation权重采用研究许可，仅用于本地比较。完整提交、权重SHA256、开发候选、逐视角结果和负面结果统一保存在 `acceptance.json.replacement_study`。

### 后续研究：多模型互验和输入尺度（2026-10-04）

菜单13将此前15个视角作为开发数据，另行固定并采集视角16～20。比较原尺寸与2倍尺寸的RAFT/FoundationStereo，以及距离一致性、视差平均和回退策略。2倍输入来自双线性放大，**没有增加真实相机信息**；视差回到原尺寸时同步除以2，测距几何保持一致。

严格互验将开发集MAE从0.217降至0.090m，但覆盖由41.4%降至31.2%。最终开发候选允许两模型距离相差不超过`min(0.5m, 较近预测距离的15%)`，至少一个模型通过1px左右一致性后取平均视差；其余区域保留上一轮输出，但拒绝FoundationStereo有效输出明确反对的距离。该规则在开发15视角同时改善覆盖、10cm准确覆盖、MAE、P95、共同像素误差及量程外误判，随后冻结。

**新5视角未通过完整验收，未升级为默认算法。** 本组姿态与上一轮不同，不能横向比较不同视角组的平均误差。

| 新验证16～20 | 上一轮RAFT+Gamma | 互验候选 |
|---|---:|---:|
| 有效覆盖率 | 25.0% | 22.9% |
| 误差≤10cm的真值覆盖率 | 9.5% | 11.0% |
| 有效预测MAE | 0.696m | 0.455m |
| 有效预测误差P95 | 2.748m | 2.713m |
| 量程外误判像素 | 59,036 | 60,832 |
| 平均推理时间/图像对 | 0.631秒 | 1.601秒 |

五个新视角MAE均下降，但空洞和量程外误判没有同时改善。已有五对实拍棋盘覆盖64.5%→66.9%，共同18,618棋盘像素的平面一致性MAE为1.112→1.050mm，仍不是独立距离真值。2倍放大也未通过开发联合检查，例如FoundationStereo的MAE由0.141升到0.501m（均使用1px筛选）。这些负面结果保存在 `refinement_study.development_trials`，不把更多模型或更大输入等同于效果更好。

运行菜单13会重新采集五个固定验证姿态；已有数据时可用Windows GPU环境执行 `simulation/refine_stereo.py` 复用同一数据。源码、权重、原始帧和标定均记录校验值；开发预测缓存会检查权重与源码提交。当前继续保留上一轮实验候选，后续应优先解决低纹理输入缺少匹配依据的问题。

### 表面纹理对照：本次最明确的提升因素（2026-10-04）

菜单14对固定视角16～20比较三组输入：均匀材质、只给地面增加随机纹理、给地面/墙面/色块/箱体增加随机纹理。三组均使用相同PBR渲染方式、照明、相机和几何；仅反照率贴图不同，避免把切换材质渲染方式误认为纹理效果。模型保持此前RAFT Middlebury + LightStereo Gamma，权重和筛选参数完全不变，传统SGBM作为独立对照。

**三组深度真值数值完全一致，几何哈希一致，左右图像与真值时间戳差为0。** 三组整图平均灰度分别为111.95、111.94、111.80，亮度均值接近；量程内低纹理区域占比从95.3%降至44.0%和30.5%。随机纹理参数与种子在看结果前固定，未按真值补洞或修正模型输出。

| 五视角汇总：RAFT+Gamma | 均匀材质控制 | 仅地面纹理 | 全场景纹理 |
|---|---:|---:|---:|
| 量程内有效测距覆盖率 | 22.0% | 90.9% | **91.5%** |
| 误差≤10cm的真值覆盖率 | 9.1% | 83.4% | **90.2%** |
| 有效预测MAE | 0.356m | 0.0322m | **0.0149m** |
| 有效预测误差P95 | 1.773m | 0.164m | **0.0575m** |
| 整图黑色比例 | 83.1% | 47.4% | 51.4% |
| 真值量程外被预测成量程内 | 53,154像素 | 65,051像素 | **16,390像素** |

全场景纹理与均匀材质共同有效的135,273像素，MAE从0.356降到0.0261m，因此改善也存在于同一组像素。SGBM有效覆盖从3.8%升至61.7%、MAE从0.118降至0.0445m，支持“增加可匹配纹理能改善测距”的解释；其量程外误判由7,297增至9,806，仍有副作用。

这里统一评估校正相机光轴方向的深度Z。全场景纹理条件中，3～5m区间有效覆盖94.6%、MAE为0.0380m、P95为0.103m；该区间误差仍高于近处，不能把整体0.0149m平均误差当作所有距离上的保证。逐距离区间统计见 `appearance_study.distance_bands`。

**低纹理是本仿真的主要瓶颈，当前证据支持改善输入纹理比单纯叠加模型更有效。** 只给地面增加纹理已恢复大部分量程内深度，但未解决远处墙面误匹配；全场景纹理进一步降低了量程外误判。全场景条件将更多超过5m的墙面恢复为无效输出，因此其整图黑色比例高于仅地面纹理条件；黑色包含正确拒绝的量程外区域，不能单独作为识别率。

该结果依赖**改变模拟场景的表面外观**，不能宣称原始低纹理图像已达到91.5%覆盖，也不能等同于真实主动投影效果。下一步应以有独立距离真值的实拍，验证非重复表面纹理或投影纹理的实际效果，并继续检查标定与同步。真实高分辨率采集、多帧融合尚未验证；真实反光、阴影、户外照明和投影设备均未在本对照中模拟。

原始图像、相同真值与预测保存在 `appearance.npz`；固定第18视角对比见 [appearance.png](results/lightstereo/appearance.png)，误差图中的紫色表示量程外误判。统计、纹理种子、几何与材质校验值统一在 `acceptance.json.appearance_study`；低覆盖因素表同步更新。菜单14可完整复现，已有采集数据时可运行 `simulation/refine_stereo.py --appearance`。采集已采用独立Gazebo/ROS进程和可靠图像传输，修复实验中发现的图像流丢失超时，同时保留严格时间戳匹配。材质实现遵循 [SDFormat PBR规范](https://sdformat.org/spec/1.7/material/)。

### LightStereo 单独复测：与融合方案使用相同输入（2026-10-04）

菜单15固定现有LightStereo权重、352×640图像、LR≤1px、0.3～5m量程，比较原灰度输入和双目同步Gamma=0.45。重新运行20对原始场景、三种纹理条件各5对、5对已有实拍棋盘，共40对图像、每对两种设置；每种设置均计算正反视差。未重新采集、训练或调整阈值。这些数据均已用于此前研究，不能称为新的独立验证集；三种纹理条件按同姿态配对报告，不与20个原始视角混为一个总体。

覆盖率为各视角0.3～5m真值区域有效覆盖的平均值，MAE为各自有效像素的汇总平均绝对误差；距离仍是相机光轴深度Z。以下每个单元格依次为 **覆盖率 / MAE**。

| 输入场景 | LightStereo原输入 | LightStereo Gamma | 已保存的RAFT+Gamma参考 |
|---|---:|---:|---:|
| 原始场景20视角 | 22.9% / 33.50cm | 30.2% / 29.92cm | 37.3% / 27.78cm |
| 均匀材质5视角 | 15.1% / 52.75cm | 19.3% / 47.87cm | 22.0% / 35.60cm |
| 仅地面纹理5视角 | 84.3% / 6.93cm | 86.3% / 6.87cm | 90.9% / 3.22cm |
| 全场景纹理5视角 | 90.1% / 2.50cm | 90.2% / 2.38cm | 91.5% / 1.49cm |

融合参考直接读取同一批数据的历史预测，先核对模型、标定与数据文件SHA256；本轮只重新推理LightStereo，没有重新计时RAFT。原始20视角中，Gamma使整图黑色比例从79.7%降至75.0%，误差≤10cm的真值覆盖从7.17%升至9.05%，量程外误判从162,746降至129,904像素。共同有效608,908像素的MAE为25.25→20.77cm，说明改善也存在于同一批像素。

**纹理对LightStereo同样关键。** 固定Gamma后，从均匀材质到全场景纹理，10cm准确覆盖由4.6%升至86.2%，整图黑色比例由84.7%降至52.1%，量程外误判由52,001降至15,287像素；共同有效115,620像素的MAE由48.21降至4.78cm。仅地面纹理的量程外误判为63,235像素，仍高于均匀材质；全场景纹理同时改善覆盖和误判。改变的是模拟场景表面外观，不能把90.2%当作原始低纹理场景或真实摄像头的效果。

筛选阶段进一步解释了黑色区域：以五视角量程内真值像素汇总为分母，Gamma在均匀材质下有49.0%因左右不一致被拒绝，增加全场景纹理后降到0.58%；后者仍有7.96%因右眼对应位置越界或校正掩码不支持被拒绝。这里是筛选阶段计数，不能把全部越界都归为真实遮挡。全纹理条件的3～5m段覆盖91.7%、MAE **6.15cm**、误差P95 **18.27cm**，远处误差明显高于整体2.38cm。

**Gamma与融合都没有在每个指标、每个场景上获胜。** 全纹理条件中Gamma仅带来很小覆盖增量，却使量程外误判从13,014增至15,287像素；原始视角11～15的10cm准确覆盖略降、P95由0.763升至0.831m。原始视角16～20中，单独Gamma覆盖18.2%、MAE0.456m，融合覆盖25.0%、MAE0.696m：融合覆盖更高，但该组平均距离误差更大。全部正负结果、分视角与分距离统计保存在同一报告，不能仅据更少黑色选择算法。

已有五对实拍棋盘的整图有效覆盖为47.60%→48.57%，棋盘覆盖97.06%→97.42%；共同17,867棋盘像素的平面一致性MAE为5.20→4.88mm。这是同一标定下的PnP参考，仍不是独立真实距离精度。桌面CPU ONNX双向前向推理约174～185ms/对，不含预处理、筛选、采集和显示；本轮未连接RK3588，不能作为NPU或板端端到端速度。

入口为菜单15，或使用`.local.json`指定的Windows Python运行 `simulation/refine_stereo.py --lightstereo`。需要先保留菜单13、14生成的`refinement.npz`、`appearance.npz`与对应`acceptance.json`。预测视差、反向视差、有效掩码和计时保存在`lightstereo.npz`，复用原图避免重复存储；统计位于`acceptance.json.lightstereo_study`，固定第18视角对比见 [lightstereo.png](results/lightstereo/lightstereo.png)。重复复测覆盖上述同名结果；原有多模型与纹理预测文件保持不变。

UWB 使用开源插件模拟带噪声、遮挡和丢包的测距，再做二维多边定位；基站与标签等高。真值只用于误差评估。当前没有视觉/UWB 融合、三维定位或无线电波形仿真。无人车/无人机提供仿真控制入口；PPO 训练目前覆盖机械臂和灵巧手。MoveIt/Nav2 依赖已安装，其完整任务仍需另行配置。

## 版本与存储

- Ubuntu 24.04 / Python 3.12；ROS 2 Jazzy、Gazebo Harmonic 及 ROS 配套包版本见 `config/ros-packages.lock`。
- PX4 v1.17.0 和 UWBPX4Sim 固定 Git 提交，见 `config/versions.json`。
- 独立 Python 环境完整依赖见 `config/learning.lock`、`config/px4.lock`；MuJoCo 3.3.7、Torch CPU 2.14.0、SB3 2.9.0。
- 项目目录保存入口、场景和结果；Linux 的 `~/robotics-lab` 保存源码、编译产物和 Python 环境。系统依赖还写入 `/opt/ros/jazzy` 及系统包目录。
- 自动识别用户和解压目录。WSLg 支持时启用 D3D12；软件渲染会明显变慢。`deployment.json` 的 graphics 项记录渲染器。本包的图形实验需要可用的 WSLg/桌面显示。

Ubuntu 基础系统包、内核和 Windows 驱动不锁定；这不是逐字节相同的整机镜像，也不是离线包。上游移除旧版本时安装会报错，不会悄悄换新版。硬件、随机噪声和调度差异会导致实验数值不同。

Ubuntu 24.04 桌面也可用普通用户运行 `bash scripts/install.sh`（系统阶段需要 sudo），再运行 `bash scripts/launch.sh mapping`。通过 `ROBOTICS_HOME` 可指定独立运行目录，安装与启动必须使用同一设置。多个项目默认共享同一用户的运行环境，请勿并行安装或重复启动同类实验。
